## Мета

Закріпити прості методи сортування — бульбашкою, вибором і вставками: навчитися трасувати їх вручну, реалізувати
мовою C++ з підрахунком порівнянь і переміщень, перевірити правильність і стійкість реалізацій та порівняти
кількість операцій з теоретичними оцінками.

ПК із компілятором C++ (g++, Visual Studio або онлайн-компілятор); конспект

## Основні теоретичні положення

Докладно методи розглянуто в лекції 11. Коротко:

- **Бульбашкою:** порівнюємо сусідні елементи й міняємо їх місцями, якщо лівий більший; за прохід найбільший
  елемент «спливає» в кінець. Прапорець обміну зупиняє роботу, щойно прохід минув без обмінів.
- **Вибором:** на кроці $i$ знаходимо мінімум невідсортованої частини й міняємо його з $a_i$.
- **Вставками:** на кроці $i$ запам'ятовуємо $a_i$, зсуваємо праворуч більші за нього елементи впорядкованої
  частини й вставляємо його на звільнене місце.

**Міри трудомісткості.** Порівняння ключів і переміщення елементів рахують окремо: порівняння зазвичай дешеве, а
переміщення великого запису може бути дорогим. Обмін (`swap`) — це три присвоювання, зсув — одне.

**Інверсія** — пара індексів $i < j$, для якої $a_i > a_j$. У відсортованому масиві інверсій немає, у масиві у
зворотному порядку їх $\frac{n(n-1)}{2}$, у випадковому — у середньому $\frac{n(n-1)}{4}$. Кожен обмін бульбашки й
кожен зсув вставок усуває рівно одну інверсію, тому кількість обмінів бульбашки й зсувів вставок дорівнює
кількості інверсій.

| Метод | Порівнянь | Переміщень | Стійкий |
| --- | --- | --- | --- |
| бульбашкою (з прапорцем) | від $n - 1$ до $\frac{n(n-1)}{2}$ | стільки обмінів, скільки інверсій | так |
| вибором | завжди $\frac{n(n-1)}{2}$ | не більше $n - 1$ обмінів | ні |
| вставками | від $n - 1$ до $\frac{n(n-1)}{2}$ | стільки зсувів, скільки інверсій | так |

**Стійкість** перевіряють на записах з однаковими ключами: рівні ключі позначають буквами ($3_a$, $3_c$) і
дивляться, чи зберігся їхній взаємний порядок після сортування.

1. **Трасування вручну.** Для масиву свого варіанта виконайте трасування трьох методів у таблицях, як у лекції 11:

   (приклад 1). Рахуйте кожне порівняння ключів, зокрема те, що завершує цикл.
3. **Перевірка правильності.** Перевірте кожну функцію на тестах із лекції 11: порожній масив, один елемент,

4. **Звірка з трасуванням.** Запустіть функції на масиві свого варіанта. Кількості порівнянь і переміщень мають

   Порівняйте результати з формулами й кількістю інверсій.
6. **Стійкість.** Відсортуйте кожним методом масив записів із прикладу 2 і визначте, які методи стійкі.
7. Виконайте **додаткове завдання** свого варіанта.
8. Запишіть висновки: який метод і на яких даних виконує найменше порівнянь, а який — найменше переміщень; як
   зростає кількість операцій зі збільшенням $n$.

### Приклад 1. Сортування вставками з лічильниками

```cpp
#include <iostream>
#include <vector>
using namespace std;

struct SortStats {
    long long comparisons = 0;   // порівнянь ключів
    long long moves = 0;         // обмінів або зсувів
};

void insertionSort(vector<int>& a, SortStats& s) {
    int n = a.size();
    for (int i = 1; i < n; i++) {
        int key = a[i];
        int j = i - 1;
        while (j >= 0) {
            s.comparisons++;
            if (a[j] <= key) break;      // місце знайдено
            a[j + 1] = a[j];             // зсуваємо більший елемент праворуч
            s.moves++;
            j--;
        }
        a[j + 1] = key;
    }
}

long long countInversions(const vector<int>& a) {
    long long count = 0;
    for (size_t i = 0; i < a.size(); i++) {
        for (size_t j = i + 1; j < a.size(); j++) {
            if (a[i] > a[j]) count++;
        }
    }
    return count;
}

int main() {
    vector<int> a = {5, 2, 4, 1, 3};
    cout << "Інверсій: " << countInversions(a) << '\n';
    SortStats s;
    insertionSort(a, s);
    cout << "Порівнянь: " << s.comparisons << ", зсувів: " << s.moves << '\n';
}
```

Програма виведе 7 інверсій, 9 порівнянь і 7 зсувів — як у трасуванні з лекції 11. Цикл `while` переписано так,
щоб кожне порівняння ключів проходило через лічильник: умову перевіряємо в тілі циклу, а коли $a_j \le key$,
виходимо з нього. Функції бульбашки й вибору доповніть лічильниками самостійно. Для масиву $[5, 2, 4, 1, 3]$
бульбашка має виконати 10 порівнянь і 7 обмінів, вибір — 10 порівнянь і 3 обміни.

### Приклад 2. Перевірка стійкості

```cpp
struct Item {
    int key;       // ключ сортування
    char label;    // позначка, щоб розрізняти рівні ключі
};

vector<Item> items = {{3, 'a'}, {1, 'b'}, {3, 'c'}, {2, 'd'}, {1, 'e'}};
```

Стійке сортування має дати $1_b, 1_e, 2_d, 3_a, 3_c$ — рівні ключі в початковому порядку. Сортування вибором
дає інший результат:

| Крок $i$ | Мінімум | Обмін | Масив після кроку |
| --- | --- | --- | --- |
| 0 | $1_b$ | $a_0 \leftrightarrow a_1$ | $1_b, 3_a, 3_c, 2_d, 1_e$ |
| 1 | $1_e$ | $a_1 \leftrightarrow a_4$ | $1_b, 1_e, 3_c, 2_d, 3_a$ |
| 2 | $2_d$ | $a_2 \leftrightarrow a_3$ | $1_b, 1_e, 2_d, 3_c, 3_a$ |
| 3 | $3_c$ | не потрібен | $1_b, 1_e, 2_d, 3_c, 3_a$ |

На кроці 1 далекий обмін переніс $3_a$ в кінець масиву, «через голову» $3_c$, — звідси нестійкість. Бульбашка й
вставки переставляють лише сусідні елементи й лише тоді, коли лівий строго більший, тому рівні елементи не
обганяють один одного.

## Контрольні запитання

1. Що вважають порівнянням і переміщенням в алгоритмі сортування? Чому їх рахують окремо?
2. Що таке інверсія? Скільки інверсій у масиві $[3, 1, 2]$? У масиві з $n$ елементів у зворотному порядку?
3. Чому кількість обмінів бульбашки дорівнює кількості інверсій?
4. Навіщо в бульбашці прапорець? Як він змінює найкращий випадок?
5. Чому сортування вибором виконує однакову кількість порівнянь для будь-якого масиву?
6. Чому сортування вставками швидке на майже впорядкованих масивах?
7. Що таке стійкість сортування? Наведіть приклад задачі, де вона важлива.
8. Чому сортування вибором нестійке? Як зробити його стійким?
9. Чому в циклі вставок умову `j >= 0` перевіряють першою?
10. Які тести потрібні, щоб перевірити програму сортування?
11. Як зміниться кількість порівнянь простих методів, якщо розмір масиву збільшити вдесятеро?
