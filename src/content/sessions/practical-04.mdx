## Мета

Реалізувати ефективні методи сортування — Шелла, злиттям, швидке й пірамідальне; навчитися правильно вимірювати
час роботи програми; експериментально порівняти методи на даних різного розміру й характеру та перевірити
теоретичні оцінки трудомісткості.

## Обладнання

ПК із компілятором C++: g++ з ключем `-O2` або Visual Studio в конфігурації **Release**; табличний процесор
(LibreOffice Calc, Excel, Google Таблиці) для графіків; конспект [лекцій 12](/lectures/12-efficient-sorting/) і
[13](/lectures/13-sorting-complexity/).

## Основні теоретичні положення

| Метод | Середній випадок | Найгірший випадок | Пам'ять | Стійкий |
| --- | --- | --- | --- | --- |
| вставками | $O(n^2)$ | $O(n^2)$ | $O(1)$ | так |
| Шелла (кроки $n/2, n/4, \dots$) | залежить від даних | $O(n^2)$ | $O(1)$ | ні |
| злиттям | $O(n \log n)$ | $O(n \log n)$ | $O(n)$ | так |
| швидке | $O(n \log n)$ | $O(n^2)$ | $O(\log n)$ | ні |
| пірамідальне | $O(n \log n)$ | $O(n \log n)$ | $O(1)$ | ні |

**Вимірювання часу.** Час вимірюють годинником `chrono::steady_clock`: він рівномірно йде вперед і не «стрибає»,
коли система коригує поточний час. Щоб вимірювання були чесними:

1. Компілюйте з оптимізацією: у налагоджувальній збірці програма в рази повільніша, і співвідношення між методами
   спотворюються.
2. Сортуйте для всіх методів **ті самі** дані, щоразу — свіжу копію.
3. Вимірюйте лише сортування: генерування даних і виведення — поза вимірюваним інтервалом.
4. Повторюйте вимірювання кілька разів і беріть **медіану**: на час впливають інші програми, кеш процесора,
   енергозбереження, а медіана, на відміну від середнього, не чутлива до поодиноких «викидів».
5. Після сортування перевіряйте `is_sorted`: час неправильного алгоритму нічого не вартий.
6. Фіксуйте зерно генератора випадкових чисел, щоб експеримент можна було повторити.

**Метод подвоєння.** Порядок трудомісткості зручно перевіряти відношенням часів $T(2n) / T(n)$:

| Трудомісткість | $T(2n) / T(n)$ |
| --- | --- |
| $O(n)$ | $\approx 2$ |
| $O(n \log n)$ | трохи більше за 2 (для $n \approx 10^6$ — близько 2,1) |
| $O(n^2)$ | $\approx 4$ |

**Характер даних.** Методи по-різному поводяться на різних даних, тому перевіряють кілька видів масивів:
випадковий, відсортований, зворотний, майже відсортований (1 % випадкових обмінів) і з багатьма повторами (лише
10 різних значень).

**Швидке сортування без переповнення стеку.** З опорним «останній елемент» на відсортованому масиві глибина
рекурсії досягає $n$, і для $n = 10^5$ програма аварійно завершується через переповнення стеку. Щоб глибина
завжди була не більшою за $\log_2 n$, рекурсивно сортують лише **меншу** частину, а більшу — у циклі того самого
виклику:

```cpp
void quickSort(vector<int>& a, int low, int high) {
    while (low < high) {
        int p = partition(a, low, high);   // розбиття Ломуто з лекції 12
        if (p - low < high - p) {          // ліва частина менша
            quickSort(a, low, p - 1);
            low = p + 1;                    // праву обробляємо в цьому ж виклику
        } else {
            quickSort(a, p + 1, high);
            high = p - 1;
        }
    }
}

void quickSort(vector<int>& a) {
    quickSort(a, 0, (int)a.size() - 1);
}
```

Від повільної роботи на невдалих даних це не рятує — лише від аварії.

### Приклад. Програма вимірювань

```cpp
#include <algorithm>
#include <chrono>
#include <functional>
#include <iostream>
#include <random>
#include <string>
#include <vector>
using namespace std;

// Реалізації — з лекцій 11–12 і розділу вище.
void shellSort(vector<int>& a);
void mergeSort(vector<int>& a);
void quickSort(vector<int>& a);
void heapSort(vector<int>& a);

enum class DataKind { Random, Sorted, Reversed, NearlySorted, FewUnique };

vector<int> makeData(int n, DataKind kind, mt19937& rng) {
    vector<int> a(n);
    for (int& x : a) x = int(rng() % 1000000);
    if (kind == DataKind::FewUnique) {
        for (int& x : a) x %= 10;                       // лише 10 різних значень
    }
    if (kind == DataKind::Sorted || kind == DataKind::NearlySorted) {
        sort(a.begin(), a.end());
    }
    if (kind == DataKind::Reversed) {
        sort(a.begin(), a.end(), greater<int>());
    }
    if (kind == DataKind::NearlySorted) {
        for (int k = 0; k < n / 100; k++) {             // 1 % випадкових обмінів
            swap(a[rng() % n], a[rng() % n]);
        }
    }
    return a;
}

using SortFunction = function<void(vector<int>&)>;

// Медіана часу кількох запусків у мілісекундах; −1, якщо масив не відсортовано.
double measureMs(const SortFunction& sortFunction, const vector<int>& data, int repeats = 5) {
    vector<double> times;
    for (int r = 0; r < repeats; r++) {
        vector<int> a = data;                           // щоразу сортуємо свіжу копію
        auto start = chrono::steady_clock::now();
        sortFunction(a);
        auto finish = chrono::steady_clock::now();
        if (!is_sorted(a.begin(), a.end())) return -1;  // помилка в сортуванні
        times.push_back(chrono::duration<double, milli>(finish - start).count());
    }
    sort(times.begin(), times.end());
    return times[times.size() / 2];
}

int main() {
    // Лямбда-вирази потрібні, бо mergeSort і quickSort перевантажені.
    vector<pair<string, SortFunction>> methods = {
        {"Шелла", [](vector<int>& a) { shellSort(a); }},
        {"злиттям", [](vector<int>& a) { mergeSort(a); }},
        {"швидке", [](vector<int>& a) { quickSort(a); }},
        {"пірамідальне", [](vector<int>& a) { heapSort(a); }},
        {"std::sort", [](vector<int>& a) { sort(a.begin(), a.end()); }},
    };
    mt19937 rng(2024);
    cout << "n";
    for (auto& method : methods) cout << '\t' << method.first;
    cout << '\n';
    for (int n = 125000; n <= 2000000; n *= 2) {
        vector<int> data = makeData(n, DataKind::Random, rng);
        cout << n;
        for (auto& method : methods) cout << '\t' << measureMs(method.second, data);
        cout << '\n';
    }
}
```

Програма виводить таблицю через табуляцію — її можна скопіювати просто в табличний процесор. Для експерименту 2
додайте цикл за видами даних `DataKind` з однаковим $n$. Якщо в консолі Windows замість українських літер
незрозумілі символи, додайте на початку `main` рядок `SetConsoleOutputCP(CP_UTF8);` (заголовок `<windows.h>`), а
у Visual Studio — ключ компілятора `/utf-8`.

## Контрольні запитання

1. Навіщо вимірювати час у збірці з оптимізацією?
2. Чому вимірювання повторюють і беруть медіану, а не одне значення?
3. Навіщо після сортування перевіряти, що масив відсортовано?
4. Як за відношенням $T(2n) / T(n)$ визначити порядок трудомісткості алгоритму?
5. Чому швидке сортування з опорним «останній елемент» повільне на відсортованому масиві? Як це виправити?
6. Чому розбиття Ломуто працює погано на масиві з багатьма однаковими елементами?
7. Чому рекурсивний виклик лише для меншої частини обмежує глибину рекурсії величиною $\log_2 n$?
8. Злиття й пірамідальне сортування мають оцінку $O(n \log n)$, як і швидке. Чому на практиці швидке сортування
   швидше?
9. Коли варто обрати сортування злиттям? Пірамідальне?
10. Чому в гібридних алгоритмах малі частини досортовують вставками?
11. Чому для вимірювань використовують `steady_clock`, а не `system_clock`?
