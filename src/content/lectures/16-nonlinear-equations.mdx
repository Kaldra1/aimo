Нелінійне рівняння виникає, коли потрібно визначити момент досягнення заданої температури, робочу точку електронного кола або параметр моделі за результатами вимірювання. Формули для точної відповіді може не існувати або вона може бути незручною для обчислення. Тоді корінь знаходять послідовним уточненням наближення. Як ми бачили в лекції 15, разом із числом потрібно отримати обґрунтування його точності. У цій лекції порівняємо чотири методи на одному рівнянні та навчимося зупиняти обчислення з контрольованою похибкою.

## Відокремлення коренів

### Постановка задачі

Потрібно знайти число $\alpha$, для якого $f(\alpha)=0$. Якщо рівняння задано як $g(x)=h(x)$, переносимо все в одну частину: $f(x)=g(x)-h(x)$. Спочатку визначаємо область допустимих значень. Корінь, отриманий після перетворень із діленням, піднесенням до квадрата або логарифмуванням, обов'язково перевіряємо в початковому рівнянні.

Розв'язування поділяють на два етапи. **Відокремлення коренів** означає пошук інтервалів, кожен із яких містить один корінь. **Уточнення** — звуження такого інтервалу або побудова послідовності наближень до потрібної точності. Невдале відокремлення не виправляється великою кількістю ітерацій: алгоритм може знайти інший корінь або не знайти жодного.

У всіх прикладах використаємо

$$
f(x)=x^3-2x-5.
$$

Значення кореня для перевірки таблиць становить приблизно $\alpha=2.0945514815423265$. Воно не використовується всередині алгоритмів: метод повинен мати власний критерій точності без знання відповіді.

### Графік, таблиця та теорема

Графічно корінь є абсцисою перетину графіка з віссю. Графік допомагає вибрати область пошуку, але його роздільна здатність не доводить ані існування, ані єдиності кореня. Дуже вузький перегин, розрив або дотик до осі можна не помітити.

Табулювання означає обчислення значень функції у вузлах сітки. Для нашого прикладу:

| $x$ | $f(x)$ |
|---:|---:|
| 1.0 | -6.000 |
| 2.0 | -1.000 |
| 2.1 | 0.061 |
| 2.5 | 5.625 |
| 3.0 | 16.000 |

**Теорема Больцано–Коші:** якщо функція неперервна на $[a;b]$ і значення на кінцях мають протилежні знаки, то всередині інтервалу існує принаймні один корінь. Якщо один кінець уже дає нуль, корінь знайдено. Неперервність є суттєвою: функція $1/x$ змінює знак між $-1$ і $1$, але кореня не має.

Для полінома неперервність виконується всюди. Маємо $f(2)=-1$, $f(3)=16$, отже на $[2;3]$ існує корінь. Крім того,

$$
f'(x)=3x^2-2\ge10>0\quad\text{на }[2;3].
$$

Функція строго зростає, тому корінь на цьому інтервалі єдиний. Для всіх наступних методів збережемо саме цей початковий інтервал, хоча таблиця вже дозволяє вибрати вужчий. Так порівняння стартових умов буде зрозумілим.

Зміна знака — достатня, але не необхідна ознака кореня. Функція $(x-1)^2$ має корінь без зміни знака; груба сітка може також пропустити два прості корені в одній комірці. Тому надійне відокремлення поєднує табулювання з аналізом похідної, області визначення та поведінки функції.

Інженерна постановка часто задає додаткові обмеження: час має бути невід'ємним, температура повинна залишатися в області застосовності моделі, а геометричний параметр — відповідати розмірам конструкції. Ці обмеження звужують пошук до того, як запускається чисельний метод. Якщо математичне рівняння має декілька коренів, програма повинна шукати саме допустимий розв'язок, а не довільну точку з малою нев'язкою.

Під час табулювання корисно зберігати не лише значення, а й відомості про невдалі обчислення функції. Якщо в деякому вузлі отримано нечислове значення, не можна просто пропустити його й оголосити інтервал між сусідніми успішними вузлами неперервним. Спочатку з'ясовують причину: це може бути межа області визначення, розрив або переповнення проміжного виразу. Кожна ситуація потребує свого виправлення, а сама зміна знака через такий вузол ще нічого не доводить.

Послідовність підготовки задачі така:

1. Визначити область допустимих аргументів та можливі розриви.
2. Побудувати графік або таблицю на потрібній області.
3. Знайти пари кінців із протилежними знаками або самі нульові значення.
4. Обґрунтувати неперервність і, за можливості, єдиність кореня.
5. Вибрати метод уточнення та необхідну абсолютну похибку аргументу.

У фрагментах C++ нижче розв'язуємо саме наведений поліном на $[2;3]$. Усі функції можна розмістити в одному файлі після спільного блоку:

```cpp
#include <cmath>
#include <iomanip>
#include <iostream>
#include <stdexcept>

double f(double x) { return (x * x - 2.0) * x - 5.0; }
double df(double x) { return 3.0 * x * x - 2.0; }

void checkTolerance(double eps) {
    if (!std::isfinite(eps) || eps <= 0.0)
        throw std::invalid_argument("Invalid tolerance");
}
```

Форма обчислення полінома зменшує кількість операцій. Під час перевірки знаків краще порівнювати їх безпосередньо, а не обчислювати добуток значень функції: для інших задач такий добуток може переповнитися, хоча обидва значення ще скінченні.

## Половинне ділення

### Ідея та оцінка точності

Метод бісекції зберігає інтервал із протилежними знаками на кінцях. Обчислюємо середину $c=(a+b)/2$ і залишаємо ту половину, на кінцях якої знак змінюється. Неперервність гарантує, що корінь залишиться всередині. Значення похідної не потрібне.

![Графік полінома на інтервалі від 2 до 3: середина 2.5 має додатне значення, тому після першого поділу лишається ліва половина](/files/lectures/16-nonlinear-equations/bisection.svg)
*Рис. 1. Перший крок методу половинного ділення*

Після $n$ звужень довжина інтервалу становить $(b_0-a_0)/2^n$. Якщо відповіддю є його середина, то

$$
|c_n-\alpha|\le\frac{b_0-a_0}{2^{n+1}}.
$$

Для заданої абсолютної похибки $\varepsilon$ достатньо

$$
n\ge\max\left(0,\left\lceil
\log_2\frac{b_0-a_0}{2\varepsilon}
\right\rceil\right).
$$

Тут $n$ рахує саме звуження, а не кількість обчислених середин. Початкова середина має індекс $0$, тому для отримання $c_n$ обчислюємо $n+1$ середин. У різних описах алгоритму нумерація відрізняється на одиницю; оцінку треба зіставляти з тим, що саме повертає програма.

Покроковий алгоритм:

1. Перевірити значення функції на кінцях і наявність зміни знака.
2. Обчислити середину та значення функції в ній.
3. Якщо половина ширини вже не перевищує допуск, повернути середину.
4. Інакше замінити один кінець серединою, зберігши різні знаки.
5. Повторювати, контролюючи ліміт кроків і машинну стагнацію.

Для $\varepsilon=10^{-4}$ потрібно $n=13$ звужень, після яких півширина становить $2^{-14}=0.00006103515625$. Отже, останній рядок гарантує потрібну точність. Фактична похибка близька до $8.02\cdot10^{-6}$, але алгоритм не може заздалегідь покладатися на це сприятливе розміщення кореня.

```cpp
double bisection(double eps) {
    checkTolerance(eps);
    double a = 2.0, b = 3.0, fa = f(a), fb = f(b);
    if (fa == 0.0) return a;
    if (fb == 0.0) return b;
    if (!std::isfinite(fa) || !std::isfinite(fb) ||
        (fa < 0.0) == (fb < 0.0))
        throw std::runtime_error("Invalid bracket");
    for (int k = 0; k < 200; ++k) {
        double c = a + (b - a) / 2.0;
        double fc = f(c);
        if (!std::isfinite(fc))
            throw std::runtime_error("Non-finite function");
        if ((b - a) / 2.0 <= eps) return c;
        if (c == a || c == b)
            throw std::runtime_error("Machine stagnation");
        if (fc == 0.0) return c;
        if ((fa < 0.0) != (fc < 0.0)) {
            b = c;
        } else {
            a = c;
            fa = fc;
        }
    }
    throw std::runtime_error("Iteration limit");
}
```

Бісекція має гарантоване зменшення інтервалу вдвічі, тобто лінійну збіжність його ширини. Недолік — вона не використовує форму графіка. Для високої точності може знадобитися більше звернень до функції, ніж у Ньютона. За машинної арифметики також припускаємо, що обчислені знаки функції надійні; для надзвичайно малих допусків потрібен окремий контроль похибки її обчислення.

Властивість збереження кореня зручно розглядати як інваріант циклу. Перед кожним проходом ми знаємо, що функція неперервна на поточному інтервалі й має різні знаки на його кінцях. Після заміни одного кінця ця властивість повинна залишитися істинною. Такий спосіб міркування допомагає перевіряти код: помилково замінений кінець порушує математичну основу алгоритму навіть тоді, коли кілька перших надрукованих наближень виглядають правдоподібно.

Не менш важливо правильно вибрати величину, яку повертає цикл. Середина поточного інтервалу має гарантію через його півширину. Якщо повернути один із кінців, без додаткової інформації можна гарантувати лише похибку в межах усієї ширини. Зміна одного рядка програми тому може вимагати зміни формули оцінювання. Під час реалізації завжди зіставляйте математичний об'єкт у доведенні з конкретною змінною, яку отримує користувач.

## Метод хорд

### Нерухомий кінець

Замість середини інтервалу можна взяти перетин хорди з віссю абсцис. Хорда через точки $(x_k,f(x_k))$ та $(b,f(b))$ дає формулу

$$
x_{k+1}=x_k-\frac{f(x_k)(b-x_k)}{f(b)-f(x_k)}.
$$

Розглядаємо **метод хорд із нерухомим кінцем** $b$. Це не метод січних, у якому кожного разу беруть два останні наближення. Існує також метод хибного положення, який оновлює кінці за знаками. На нашій зростаючій опуклій функції він залишає правий кінець нерухомим і породжує ту саму послідовність.

На $[2;3]$ маємо $f''(x)=6x>0$. Графік опуклий, тому хорда лежить над ним, а її перетин з віссю розташований ліворуч від кореня. Фіксуємо $b=3$, для якого $f(b)f''(b)>0$, і починаємо з $x_0=2$. Наближення зростають до кореня, залишаючись у початковому інтервалі.

Алгоритм полягає у фіксації відповідного кінця, обчисленні перетину хорди, перевірці точності й повторенні з новою рухомою точкою. Перед діленням перевіряємо знаменник. Загалом придатність фіксованого кінця обґрунтовують сталістю знаків першої та другої похідних, а не лише виглядом графіка на екрані.

Для першого кроку отримуємо

$$
x_1=2-\frac{(-1)(3-2)}{16-(-1)}
=2+\frac1{17}\approx2.0588235294.
$$

Оскільки $f'(x)\ge10$, теорема про середнє дає $|x_k-\alpha|\le|f(x_k)|/10$. На кроці $12$ ця межа приблизно $6.862\cdot10^{-7}$, отже точність $10^{-6}$ досягнута. Це саме оцінка похибки аргументу, а не вимога, щоб сама нев'язка була меншою за $10^{-6}$.

```cpp
double chord(double eps) {
    checkTolerance(eps);
    constexpr double b = 3.0, m = 10.0;
    const double fb = f(b);
    double x = 2.0;
    for (int k = 0; k < 200; ++k) {
        double fx = f(x);
        if (std::abs(fx) / m <= eps) return x;
        double denominator = fb - fx;
        if (denominator == 0.0)
            throw std::runtime_error("Zero chord denominator");
        double next = x - fx * (b - x) / denominator;
        if (!std::isfinite(next) || next < 2.0 || next > 3.0)
            throw std::runtime_error("Left the verified interval");
        if (next == x)
            throw std::runtime_error("Machine stagnation");
        x = next;
    }
    throw std::runtime_error("Iteration limit");
}
```

Після обчислення $f(b)$ потрібне одне нове значення функції на крок. Проте збіжність зазвичай лише лінійна, і невдало розміщений нерухомий кінець може її сповільнювати. Малий крок хорди без додаткової оцінки ще не гарантує малу похибку: послідовність може просуватися до кореня дуже повільно.

## Метод Ньютона

### Дотична замість хорди

Метод Ньютона замінює функцію її лінійним наближенням у поточній точці:

$$
f(x)\approx f(x_k)+f'(x_k)(x-x_k).
$$

Прирівнявши праву частину до нуля, отримуємо

$$
x_{k+1}=x_k-\frac{f(x_k)}{f'(x_k)}.
$$

Геометрично нове наближення — абсциса перетину дотичної з віссю. На відміну від хорди, дотична враховує локальний нахил графіка. Це часто дає значно швидше уточнення поблизу простого кореня.

![Графік полінома та дві дотичні: дотична в точці 3 дає наближення 2.36, а наступна — приблизно 2.1272](/files/lectures/16-nonlinear-equations/newton.svg)
*Рис. 2. Дотичні методу Ньютона*

Зручна достатня умова для нашої ситуації: функція двічі неперервно диференційовна, на інтервалі є зміна знака, $f'$ не дорівнює нулю, а $f''$ має сталий ненульовий знак. Тоді початковий кінець обирають за умовою

$$
f(x_0)f''(x_0)>0.
$$

Це правило працює разом із переліченими припущеннями, а не саме по собі для будь-якої функції. У прикладі обираємо $x_0=3$, бо обидва множники додатні. Послідовність рухається до кореня справа.

Порядок обчислень: знайти початкову точку, обчислити функцію й похідну, перевірити можливість ділення, виконати крок дотичної, оцінити точність та повторити. Якщо в загальній задачі крок виходить за надійний інтервал, його можна замінити бісекцією; такий захист поєднує швидкість Ньютона з контролем інтервалу.

| 0 | 3.000000000000 | $16$ |
| 1 | 2.360000000000 | $3.424256$ |
| 2 | 2.127196780159 | $0.3710998462$ |
| 3 | 2.095136036934 | $0.0065266260$ |
| 4 | 2.094551673824 | $2.1461431\cdot10^{-6}$ |
| 5 | 2.094551481542 | $2.3\cdot10^{-13}$ |

Нев'язку обчислено до округлення значень у стовпці $x_k$. Уже на четвертому кроці межа $|f(x_4)|/10$ становить приблизно $2.147\cdot10^{-7}$ і підтверджує точність $10^{-6}$.

```cpp
double newton(double eps) {
    checkTolerance(eps);
    double x = 3.0;
    for (int k = 0; k < 100; ++k) {
        double fx = f(x);
        if (std::abs(fx) / 10.0 <= eps) return x;
        double derivative = df(x);
        if (!std::isfinite(derivative) || derivative == 0.0)
            throw std::runtime_error("Invalid derivative");
        double next = x - fx / derivative;
        if (!std::isfinite(next) || next < 2.0 || next > 3.0)
            throw std::runtime_error("Left the verified interval");
        if (next == x)
            throw std::runtime_error("Machine stagnation");
        x = next;
    }
    throw std::runtime_error("Iteration limit");
}
```

Для простого кореня, де $f'(\alpha)\ne0$, і достатньо близького початкового наближення метод має **квадратичну збіжність**:

$$
|e_{k+1}|\approx
\left|\frac{f''(\alpha)}{2f'(\alpha)}\right||e_k|^2,
\qquad e_k=x_k-\alpha.
$$

Після входження в цю область кількість правильних цифр приблизно подвоюється. Це локальна властивість: далекий старт може спричинити цикл, вихід з області визначення або збіжність до іншого кореня. Для кратного кореня звичайний Ньютон зазвичай збігається лише лінійно. Дуже мала похідна також робить поправку великою й чутливою до округлення.

Квадратична збіжність не означає, що нев'язка зменшується в однакову кількість разів на кожному кроці. Навпаки, у сприятливій локальній області покращення прискорюється. Перші переходи від далекого старту можуть бути порівняно скромними, після чого похибка різко падає. Біля межі машинної точності цей режим закінчується: округлення функції та поправки стають порівнянними з похибкою наближення, і нові ітерації перестають додавати достовірні цифри.

У прикладній програмі похідну потрібно перевіряти так само уважно, як початкову функцію. Помилка в аналітичному диференціюванні може створити зовні правдоподібну, але повільну або розбіжну послідовність. Для налагодження корисно зіставити знак і порядок величини похідної з поведінкою функції поблизу кількох звичайних точок. При цьому наближене чисельне диференціювання саме має похибку, тому воно є допоміжною перевіркою, а не автоматичним доказом правильності.

## Проста ітерація

### Перетворення рівняння

Перепишемо рівняння як $x=\varphi(x)$ та будуватимемо

$$
x_{k+1}=\varphi(x_k).
$$

Не кожне рівносильне перетворення дає збіжний процес. Достатньо, щоб $\varphi$ переводила замкнений інтервал у себе та виконувалася умова стискання

$$
|\varphi'(x)|\le q<1
\quad\text{для всіх }x\in[a;b].
$$

Тоді в інтервалі є єдина нерухома точка, а послідовність збігається до неї з будь-якого старту в цьому інтервалі. Вимога переведення інтервалу в себе не менш важлива за межу похідної: без неї наступний крок може залишити область, де проведено оцінювання.

Для нашого рівняння оберемо

$$
\varphi(x)=\sqrt[3]{2x+5},\qquad
\varphi'(x)=\frac{2}{3(2x+5)^{2/3}}.
$$

На $[2;3]$ образ інтервалу дорівнює приблизно $[2.080083823;2.223980091]$ і лежить усередині $[2;3]$. Найбільша похідна досягається при $x=2$ та становить приблизно $0.154080284$. Для зручності беремо гарантовано більшу межу $q=0.16$.

Алгоритм: вибрати збіжне перетворення, установити $q$, задати $x_0$, обчислювати наступні значення та зупинитися за оцінкою похибки. Апріорна й апостеріорна оцінки мають вигляд

$$
|x_k-\alpha|\le\frac{q^k}{1-q}|x_1-x_0|,
\qquad
|x_k-\alpha|\le\frac{q}{1-q}|x_k-x_{k-1}|\quad(k\ge1).
$$

Друга оцінка особливо зручна в програмі: використовує два вже обчислені наближення. Множник перед різницею принциповий, адже за $q$, близького до одиниці, малий крок може відповідати ще значній похибці.

Походження цієї оцінки можна пояснити без знання самого кореня. Через стискання кожна наступна різниця між сусідніми наближеннями не перевищує попередню, помножену на коефіцієнт стискання. Відстань від поточної точки до границі не більша за суму всіх майбутніх переміщень. Ці переміщення обмежені членами спадної геометричної прогресії; після її підсумовування й отримуємо наведений множник. Отже, оцінка враховує не лише вже виконаний крок, а й увесь залишок нескінченного процесу.

Це також пояснює практичну цінність меншого коефіцієнта стискання. Якщо вдалося знайти рівносильне перетворення з меншою верхньою межею похідної, майбутній залишок зменшується швидше. Проте порівнювати потрібно повну вартість: складніше перетворення може потребувати дорогих обчислень. У нашому прикладі кубічний корінь дає коротку формулу, просту перевірку області та достатньо малу межу похідної, тому він є зручним навчальним вибором.

### Таблиця ітерацій

Починаємо з $x_0=2$. Перший крок — $x_1=\sqrt[3]{9}\approx2.0800838231$.

| $k$ | $x_k$ | $f(x_k)$ |
|---:|---:|---:|
| 0 | 2.0000000000 | -1.0000000000 |
| 1 | 2.0800838231 | -0.1601676461 |
| 2 | 2.0923506778 | -0.0245337095 |
| 3 | 2.0942169960 | -0.0037326364 |
| 4 | 2.0945006522 | -0.0005673124 |
| 5 | 2.0945437575 | -0.0000862107 |
| 6 | 2.0945503078 | -0.0000131006 |
| 7 | 2.0945513032 | -0.0000019907 |

На сьомому кроці різниця сусідніх наближень приблизно $9.953745\cdot10^{-7}$. Помноживши її на $0.16/0.84$, отримуємо межу приблизно $1.896\cdot10^{-7}$. Вона підтверджує точність $10^{-6}$.

```cpp
double fixedPoint(double eps) {
    checkTolerance(eps);
    constexpr double q = 0.16;
    double x = 2.0;
    for (int k = 0; k < 200; ++k) {
        double next = std::cbrt(2.0 * x + 5.0);
        if (!std::isfinite(next) || next < 2.0 || next > 3.0)
            throw std::runtime_error("Left the verified interval");
        double bound = q / (1.0 - q) * std::abs(next - x);
        if (bound <= eps && std::abs(f(next)) / 10.0 <= eps)
            return next;
        if (next == x)
            throw std::runtime_error("Machine stagnation");
        x = next;
    }
    throw std::runtime_error("Iteration limit");
}
```

Додаткова перевірка нев'язки в цьому конкретному прикладі проста, бо відома нижня межа похідної початкової функції. Для іншого рівняння потрібно заново обґрунтувати всі сталі. Виклик `std::cbrt` явно означає дійсний кубічний корінь, зокрема й для від'ємних аргументів.

Інше рівносильне перетворення, $\varphi(x)=(x^3-5)/2$, має похідну $3x^2/2$, яка на $[2;3]$ не менша за $6$. Воно не є стисканням і поблизу нашого кореня нестійке. Отже, проста форма формули ще не свідчить про придатність ітерації.

## Зупинка й вибір методу

### Що насправді перевіряє програма

Найпоширеніші ознаки зупинки — мала ширина інтервалу, малий крок та мала нев'язка $r_k=f(x_k)$. Вони вимірюють різні речі. Ширина дає геометричну гарантію, якщо корінь збережено всередині; крок показує зміну наближення; нев'язка показує, наскільки добре виконується рівняння.

Як ми бачили в лекції 15, масштаб важливий. Множення рівняння на дуже малу сталу не змінює кореня, але робить нев'язку малою майже всюди. Тому умова $|f(x)|\le\varepsilon$ без аналізу масштабу не гарантує $|x-\alpha|\le\varepsilon$.

Якщо між наближенням і коренем виконується $|f'(x)|\ge m>0$, то

$$
|x-\alpha|\le\frac{|f(x)|}{m}.
$$

Для нашого інтервалу $m=10$. Якщо сама функція обчислюється з абсолютною похибкою не більшою за $E_f$, чисельник гарантії потрібно замінити на $|\widetilde{f}(x)|+E_f$. Навчальні програми використовують допуски, помітно більші за машинний рівень, але не є засобом інтервального доведення точності до останнього біта.

Малий крок Ньютона може означати успіх, а може виникнути через округлення. Якщо `next == x`, подальші повторення не додають інформації. Потрібно перевірити нев'язку та оцінку похибки, а за їх невиконання повідомити про стагнацію. Ліміт ітерацій — це захист програми, а не математичний критерій успіху.

Для аргументів різного масштабу застосовують комбінований допуск $\tau_{\mathrm{abs}}+\tau_{\mathrm{rel}}|x|$. Допуск аргументу має одиниці аргументу, допуск нев'язки — одиниці функції. Порівнювати їх як однакові числа без пояснення небажано, особливо в прикладній задачі з фізичними величинами.

### Порівняння

| Метод | Потрібна інформація | Збіжність | Сильна сторона | Обмеження |
|---|---|---|---|---|
| Бісекція | Неперервність, інтервал зі зміною знака | Лінійна за шириною | Передбачувана гарантія похибки | Порівняно багато кроків |
| Хорди з нерухомим кінцем | Значення функції, придатний кінець | Зазвичай лінійна | Не обчислює похідну на кожному кроці | Можливе повільне просування |
| Ньютон | Функція, похідна, вдалий старт | Локально квадратична для простого кореня | Швидке точне уточнення | Проблеми з малою похідною й далеким стартом |
| Проста ітерація | Відображення інтервалу в себе, $q<1$ | Лінійна з оцінкою через $q$ | Проста реалізація та явна оцінка | Потрібно знайти збіжне перетворення |

Порівнювати лише кількість кроків недостатньо. Якщо похідна дорога, один крок Ньютона може коштувати значно більше за крок бісекції. Якщо функція задана складною моделлю, повторне використання вже обчислених значень теж впливає на час. Для цієї лекції важливіше навчитися обґрунтовувати результат, ніж оголосити один метод найкращим для всіх задач.

Зібравши попередні фрагменти, можна виконати порівняльний запуск:

```cpp
int main() {
    try {
        constexpr double eps = 1e-6;
        std::cout << std::setprecision(12)
                  << bisection(eps) << '\n'
                  << chord(eps) << '\n'
                  << newton(eps) << '\n'
                  << fixedPoint(eps) << '\n';
    } catch (const std::exception& error) {
        std::cerr << error.what() << '\n';
        return 1;
    }
}
```

Усі чотири відповіді повинні узгоджуватися з коренем у межах заданої похибки, але не зобов'язані збігатися цифра в цифру. Для перевірки реалізації корисно зберігати номер кроку, наближення, нев'язку та власну оцінку похибки методу. Саме така таблиця дозволяє відрізнити швидке зближення від передчасної зупинки.

## Підсумки

- Відокремлення встановлює область пошуку кореня, уточнення забезпечує потрібну точність.
- Теорема Больцано–Коші потребує неперервності та зміни знака; єдиність обґрунтовують окремо.
- Бісекція зберігає корінь усередині інтервалу та дає явну оцінку кількості звужень.
- Метод хорд із нерухомим кінцем використовує перетин хорди з віссю й зазвичай збігається лінійно.
- Ньютон має локальну квадратичну збіжність для простого кореня, якщо старт та похідна придатні.
- Проста ітерація потребує відображення області в себе й умови стискання; малий крок оцінюють через $q$.
- Нев'язка, похибка аргументу та машинна стагнація — різні поняття, які потрібно розрізняти в програмі.
