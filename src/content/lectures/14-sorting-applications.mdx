Сортування рідко буває метою саме по собі: зазвичай його виконують, щоб потім швидко щось знайти, згрупувати
чи порівняти. У цій лекції розглянемо типові задачі, які розв'язуються сортуванням, бінарний пошук і стандартну
бібліотеку алгоритмів C++ — готові, ретельно оптимізовані функції, якими користуються в реальних програмах замість
власних реалізацій.

## Навіщо сортувати

Після сортування однакові й близькі значення опиняються поруч, а масив набуває структури, яку можна використати.

| Задача | Без сортування | Із сортуванням |
| --- | --- | --- |
| багаторазовий пошук елемента | $O(n)$ на кожен запит | $O(\log n)$ на запит бінарним пошуком |
| чи є в масиві дублікати | перебір пар — $O(n^2)$ | порівняти сусідів — $O(n \log n)$ разом із сортуванням |
| кількість різних значень | $O(n^2)$ | $O(n \log n)$ |
| медіана, $k$-те за величиною | — | взяти елемент з індексом $k$ |
| перетин двох множин | $O(n \cdot m)$ | один спільний прохід — $O(n + m)$ після сортування |
| найближча пара чисел | $O(n^2)$ | найменша різниця сусідів — $O(n \log n)$ |
| чи є слова анаграмами | — | порівняти слова з відсортованими буквами |

Приклад: чи містить масив повтори?

```cpp
bool hasDuplicates(vector<int> a) {           // копія, щоб не змінювати оригінал
    sort(a.begin(), a.end());
    for (size_t i = 1; i < a.size(); i++) {
        if (a[i] == a[i - 1]) return true;     // однакові елементи тепер сусіди
    }
    return false;
}
```

## Бінарний пошук

У відсортованому масиві елемент можна знайти за $O(\log n)$ порівнянь. **Ідея:** порівнюємо шуканий $x$ із
середнім елементом; якщо $x$ менший — шукаємо в лівій половині, якщо більший — у правій. Щоразу область пошуку
зменшується вдвічі.

```cpp
int binarySearch(const vector<int>& a, int x) {
    int low = 0, high = (int)a.size() - 1;
    while (low <= high) {
        int mid = low + (high - low) / 2;      // не (low + high) / 2 — можливе переповнення
        if (a[mid] == x) return mid;
        if (a[mid] < x) low = mid + 1;
        else high = mid - 1;
    }
    return -1;                                  // не знайдено
}
```

Трасування пошуку $x = 23$ у масиві $[2, 5, 8, 12, 16, 23, 38, 56, 72, 91]$:

| Крок | low | high | mid | a[mid] | Дія |
| --- | --- | --- | --- | --- | --- |
| 1 | 0 | 9 | 4 | 16 | $16 < 23$, шукаємо праворуч |
| 2 | 5 | 9 | 7 | 56 | $56 > 23$, шукаємо ліворуч |
| 3 | 5 | 6 | 5 | 23 | знайдено, індекс 5 |

Для мільйона елементів знадобиться не більше 20 кроків, для мільярда — 30. Але бінарний пошук працює **лише на
відсортованих даних**: сортування ($O(n \log n)$) окупається, якщо запитів багато.

Типові помилки: `low < high` замість `low <= high` (пропускає останній елемент), `low = mid` замість
`low = mid + 1` (нескінченний цикл), пошук у невідсортованому масиві.

## Бібліотека алгоритмів C++

Заголовок `<algorithm>` містить десятки готових алгоритмів. Вони працюють із **діапазоном ітераторів**
`[first, last)` — від першого елемента включно до останнього не включно. Для вектора це `a.begin()` і `a.end()`,
для звичайного масиву — вказівники `arr` і `arr + n`.

### Сортування

| Функція | Що робить | Складність |
| --- | --- | --- |
| `sort(first, last)` | сортує за зростанням (інтроспективне сортування) | $O(n \log n)$ |
| `stable_sort(first, last)` | стійке сортування (злиттям) | $O(n \log n)$ |
| `partial_sort(first, middle, last)` | впорядковує лише перші $k$ найменших | $O(n \log k)$ |
| `nth_element(first, nth, last)` | ставить на місце $k$-й елемент, ліворуч менші, праворуч більші | $O(n)$ у середньому |
| `is_sorted(first, last)` | перевіряє, чи відсортовано | $O(n)$ |

```cpp
vector<int> a = {5, 2, 7, 1, 9, 3, 8, 4};

sort(a.begin(), a.end());                          // 1 2 3 4 5 7 8 9
sort(a.begin(), a.end(), greater<int>());          // 9 8 7 5 4 3 2 1

vector<int> b = {5, 2, 7, 1, 9, 3, 8, 4};
partial_sort(b.begin(), b.begin() + 3, b.end());   // три найменші попереду: 1 2 3 …

vector<int> c = {5, 2, 7, 1, 9, 3, 8, 4};
nth_element(c.begin(), c.begin() + 4, c.end());    // c[4] == 5 — як у відсортованому масиві
```

`nth_element` — найшвидший спосіб знайти медіану чи $k$-те значення без повного сортування.

### Пошук у відсортованому діапазоні

| Функція | Що повертає |
| --- | --- |
| `binary_search(first, last, x)` | `true`, якщо $x$ є |
| `lower_bound(first, last, x)` | ітератор на перший елемент, не менший за $x$ |
| `upper_bound(first, last, x)` | ітератор на перший елемент, більший за $x$ |
| `equal_range(first, last, x)` | пару `lower_bound` і `upper_bound` |

Різниця `upper_bound − lower_bound` дорівнює кількості входжень $x$:

```cpp
vector<int> a = {1, 2, 2, 2, 5, 7};
auto lo = lower_bound(a.begin(), a.end(), 2);      // на першу 2 (індекс 1)
auto hi = upper_bound(a.begin(), a.end(), 2);      // на 5 (індекс 4)
cout << hi - lo << '\n';                            // 3 входження
```

### Інші корисні алгоритми

| Функція | Призначення |
| --- | --- |
| `min_element`, `max_element` | ітератор на найменший / найбільший елемент — $O(n)$, сортувати не треба |
| `count(first, last, x)` | кількість елементів, рівних $x$ |
| `reverse(first, last)` | обернути порядок |
| `unique(first, last)` | прибрати **сусідні** повтори (зсуває унікальні вперед, повертає новий кінець) |
| `merge(…)` | злити два відсортовані діапазони в третій |
| `accumulate` (з `<numeric>`) | сума елементів |

Ідіома «залишити лише унікальні значення» поєднує три функції:

```cpp
sort(a.begin(), a.end());
a.erase(unique(a.begin(), a.end()), a.end());
```

## Власний порядок: компаратори

Усі функції сортування приймають необов'язковий **компаратор** — функцію двох аргументів, яка повертає `true`,
якщо перший має стояти **раніше** за другий. Зручно писати його лямбда-виразом.

Відсортуємо студентів за середнім балом (від більшого до меншого), а за однакового бала — за прізвищем:

```cpp
struct Student {
    string surname;
    double average;
};

vector<Student> group = {
    {"Коваль", 4.5}, {"Бойко", 4.8}, {"Андрієнко", 4.5}, {"Дмитренко", 3.9},
};

sort(group.begin(), group.end(), [](const Student& x, const Student& y) {
    if (x.average != y.average) return x.average > y.average;   // спочатку за балом
    return x.surname < y.surname;                                // потім за прізвищем
});
// Бойко 4.8, Андрієнко 4.5, Коваль 4.5, Дмитренко 3.9
```

**Вимоги до компаратора.** Компаратор має задавати «строгий» порядок — поводитися як знак `<`:

- для однакових елементів повертати `false` — тому пишуть `<`, а не `<=`;
- бути узгодженим: якщо $x$ раніше за $y$, а $y$ раніше за $z$, то $x$ раніше за $z$.

Компаратор із `<=` — поширена помилка: `std::sort` з таким порядком може працювати неправильно й навіть вийти за
межі масиву.

Замість складного компаратора можна скористатися **стійкістю**: спершу відсортувати за прізвищем, потім
`stable_sort` за балом — у межах однакового бала прізвища лишаться за абеткою.

## Функція qsort мови C

У мові C (і в старому коді на C++) використовують `qsort` із `<cstdlib>`:

```cpp
int compareInts(const void* x, const void* y) {
    int a = *(const int*)x, b = *(const int*)y;
    return (a > b) - (a < b);      // від'ємне, нуль або додатне
}

int arr[] = {5, 2, 7, 1};
qsort(arr, 4, sizeof(int), compareInts);
```

`qsort` не знає типу елементів і викликає компаратор через вказівник, тому зазвичай повільніший за `std::sort`, а
помилку в типах компілятор не помітить. У C++ віддавайте перевагу `std::sort`.

## Сортування в інших мовах

| Мова | Функція | Алгоритм | Стійке |
| --- | --- | --- | --- |
| Python | `sorted(xs, key=…)`, `xs.sort()` | Timsort (злиття + вставки) | так |
| Java | `Arrays.sort` для примітивів | швидке з двома опорними | ні |
| Java | `Arrays.sort` для об'єктів, `Collections.sort` | Timsort | так |
| JavaScript | `array.sort((a, b) => a - b)` | залежить від рушія | так (з ES2019) |

Пастка JavaScript: без компаратора `sort` порівнює елементи **як рядки**, тому `[10, 9, 1].sort()` дає
`[1, 10, 9]`.

## Практичні поради

- **Не пишіть власне сортування** в робочому коді: бібліотечне швидше, перевірене й стійке до «поганих» даних.
  Власні реалізації — для навчання й особливих випадків.
- **Не сортуйте без потреби.** Для мінімуму чи максимуму досить `min_element` ($O(n)$), для $k$ найкращих —
  `partial_sort` або `nth_element`, для перевірки «чи є елемент» при частих вставках — `std::set` або
  `std::unordered_set`.
- **Сортуйте один раз, шукайте багато разів.**
- **Обережно з дійсними числами:** значення NaN порушує порядок, і компаратор перестає бути строгим.
- **Великі записи** сортуйте через масив індексів або вказівників, щоб не копіювати дані.

## Підсумки

- Сортування спрощує пошук, виявлення дублікатів, підрахунок частот, пошук медіани, перетин множин.
- Бінарний пошук у відсортованому масиві виконує $O(\log n)$ порівнянь; важливі точні межі циклу.
- `<algorithm>` містить `sort`, `stable_sort`, `partial_sort`, `nth_element`, `binary_search`, `lower_bound`,
  `upper_bound`, `unique`, `merge` та інші функції, що працюють із діапазоном `[first, last)`.
- Власний порядок задають компаратором; він має бути строгим (`<`, а не `<=`).
- `qsort` з C менш зручний і безпечний за `std::sort`.
- У Python і Java для об'єктів використовують стійкий Timsort; у JavaScript без компаратора числа порівнюються як
  рядки.

2. Опишіть бінарний пошук. Чому він працює лише на відсортованих даних?
3. Скільки кроків бінарного пошуку потрібно для масиву з мільйона елементів?
4. Чому середину обчислюють як `low + (high - low) / 2`?
5. Чим `sort` відрізняється від `stable_sort`? Коли потрібне стійке сортування?
6. Для чого `partial_sort` і `nth_element`? Як знайти медіану масиву за $O(n)$ у середньому?
7. Що повертають `lower_bound` і `upper_bound`? Як за їх допомогою порахувати кількість входжень?
8. Як залишити в масиві лише унікальні значення?
9. Напишіть компаратор для сортування рядків за довжиною, а за однакової довжини — за абеткою.
10. Чому компаратор не можна писати зі знаком `<=`?
11. Чим `qsort` гірший за `std::sort`?
12. Чому в JavaScript `[10, 9, 1].sort()` повертає `[1, 10, 9]`?
