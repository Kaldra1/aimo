Алгоритми оточують нас усюди: додавання чисел у стовпчик, пошук маршруту в навігаторі, стиснення фотографії,
перевірка пароля. Програміст щодня придумує й записує алгоритми, а комп'ютер їх виконує. У цій лекції
з'ясуємо, що таке алгоритм, якими властивостями він має володіти, чому математикам знадобилося точне означення
алгоритму і які моделі алгоритмів ми вивчатимемо в курсі.

## Звідки слово «алгоритм»

Слово походить від імені перського вченого IX століття **Мухаммада ібн Муси аль-Хорезмі**. Його трактат про
індійську позиційну систему числення й правила арифметичних дій у ній поширився в Європі в латинському
перекладі, що починався словами «Dixit Algorithmi» — «сказав аль-Хорезмі». Так ім'я автора перетворилося на
назву правил обчислень: спершу «алгоризм» — мистецтво рахувати десятковими цифрами, а згодом «алгоритм» —
будь-яка точна процедура.

Самі ж алгоритми значно давніші. **Алгоритм Евкліда** для знаходження найбільшого спільного дільника описано в
«Началах» Евкліда (близько 300 р. до н. е.) — він і досі використовується в криптографії й комп'ютерній алгебрі.

## Інтуїтивне поняття алгоритму

Неформально **алгоритм** — це скінченний набір точних інструкцій, який визначає послідовність дій для
розв'язання задач певного класу: виконуючи ці дії для будь-яких допустимих вхідних даних, отримуємо результат
за скінченну кількість кроків.

Алгоритм завжди призначений для деякого **виконавця** — людини, робота, комп'ютера, абстрактної машини.
Виконавець уміє робити обмежений набір дій — **систему команд виконавця**. Алгоритм має складатися лише з
команд, які виконавець розуміє. Інструкція «знайди корінь рівняння» — не алгоритм для калькулятора, а
послідовність натискань клавіш — алгоритм.

Приклад: алгоритм Евкліда для натуральних чисел $a$ і $b$.

1. Якщо $b = 0$, результат — $a$; кінець.
2. Інакше обчислити остачу $r$ від ділення $a$ на $b$.
3. Замінити $a$ на $b$, $b$ на $r$ і повернутися до кроку 1.

Для $a = 48$, $b = 18$: $(48, 18) \to (18, 12) \to (12, 6) \to (6, 0)$, результат 6.

## Властивості алгоритму

Щоб інструкцію можна було назвати алгоритмом, вона має володіти такими властивостями.

**Дискретність.** Процес виконання складається з окремих кроків. Кожен крок виконується за скінченний час, і
лише після його завершення починається наступний.

**Визначеність (детермінованість).** Кожен крок описано точно й однозначно, без можливості різного тлумачення.
Для тих самих вхідних даних алгоритм завжди виконує ті самі дії й дає той самий результат. Інструкція «додайте
трохи солі» цієї властивості не має.

**Зрозумілість (формальність).** Кожен крок має бути командою з системи команд виконавця. Виконавцю не
потрібно розуміти мету алгоритму — досить механічно виконувати команди.

**Результативність (скінченність).** Для допустимих вхідних даних алгоритм зупиняється через скінченну кількість
кроків і видає результат (або повідомлення, що розв'язку немає). «Ділити число навпіл, доки не отримаємо нуль»
— не алгоритм: для додатного числа ділення навпіл ніколи не дасть рівно нуль.

**Масовість.** Алгоритм розв'язує не одну конкретну задачу, а цілий клас задач — для різних вхідних даних.
Алгоритм Евкліда працює для будь-якої пари натуральних чисел, а не лише для 48 і 18.

Окремо варто сказати про **коректність**: алгоритм має давати **правильний** результат. Властивості вище
гарантують, що процес має сенс; коректність доводять окремо — міркуванням, трасуванням, тестами.

## Способи запису алгоритмів

Один і той самий алгоритм можна записати по-різному:

- **словесно** — пронумерованими кроками природною мовою, як алгоритм Евкліда вище;
- **псевдокодом** — напівформальною мовою з конструкціями «якщо», «поки», «для»;
- **графічно** — схемою (блок-схемою) за стандартом ГОСТ 19.701-90 або структурограмою;
- **програмою** мовою програмування.

Цим способам присвячено лекції 8 і 9. Той самий алгоритм Евкліда мовою C++:

```cpp
int gcd(int a, int b) {
    while (b != 0) {
        int r = a % b;
        a = b;
        b = r;
    }
    return a;
}
```

## Навіщо точне означення алгоритму

Інтуїтивного розуміння досить, щоб **придумати** алгоритм: коли він перед очима, ми бачимо, що він
існує. Але як довести, що алгоритму для певної задачі **не існує взагалі**? Для цього потрібно точно знати, що
саме ми перебираємо, — тобто мати математичне означення алгоритму.

Питання не абстрактне. У 1900 році Давид Гільберт сформулював список важливих проблем математики. **Десята
проблема Гільберта** вимагала знайти загальний метод, який за будь-яким діофантовим рівнянням (многочленом із
цілими коефіцієнтами) визначає, чи має воно цілі розв'язки. Десятиліттями такий метод шукали — і лише в 1970 році
Юрій Матіясевич, спираючись на роботи М. Девіса, Х. Патнема і Дж. Робінсон, довів, що **такого алгоритму не
існує**. Це доведення було б неможливим без точної моделі алгоритму.

У 1928 році Гільберт і Аккерман поставили ще ширше питання — **проблему розв'язності** (Entscheidungsproblem):
чи існує алгоритм, який для будь-якого твердження формальної логіки визначає, чи воно доводиться. У 1936 році
А. Черч і А. Тюрінг незалежно довели, що ні. Для цього обидва спершу дали точне означення алгоритму.

## Моделі алгоритмів

У 1930–1950-х роках з'явилося кілька математичних уточнень поняття алгоритму. Їх можна поділити на три підходи.

### Обчислення функцій: рекурсивні функції

Алгоритм розглядають як спосіб обчислити функцію натуральних аргументів. Беруть кілька найпростіших функцій
(нуль, наступне число, вибір аргументу) й дозволяють будувати з них нові за допомогою композиції, примітивної
рекурсії й мінімізації. Функції, які можна так отримати, називають **рекурсивними**. Цей підхід розвивали К. Гедель,
Ж. Ербран, С. Клін, А. Черч.

### Абстрактні машини

Алгоритм — програма для простої уявної машини з нескінченною пам'яттю. **Машина Тюрінга** (А. Тюрінг, 1936) має
стрічку з символами, головку читання/запису й скінченну кількість станів. **Машина Поста** (Е. Пост, 1936) ще
простіша: комірки стрічки лише порожні або з міткою. Ці моделі найближчі до реальних комп'ютерів, і саме з ними
ми працюватимемо в лабораторних роботах 1–2 за допомогою емуляторів на сайті.

### Перетворення слів: нормальні алгоритми Маркова

Алгоритм — набір правил заміни підслів у слові (А. Марков, 1950-ті). Ця модель близька до обробки текстів,
компіляторів і систем перетворення формул. Їй присвячено лекції 6–7 і практичні заняття 1–2.

### Теза Черча–Тюрінга

Виявилося, що **всі ці моделі рівносильні**: функцію, яку можна обчислити в одній моделі, можна обчислити й у будь-якій
іншій. Це доведено строго. На цьому ґрунтується **теза Черча–Тюрінга**:

> Будь-яка функція, яку можна обчислити інтуїтивно зрозумілим алгоритмом, обчислюється машиною Тюрінга.

Це не теорема: поняття «інтуїтивно зрозумілий алгоритм» не має точного означення, тож довести тезу неможливо.
Проте за майже століття ніхто не знайшов алгоритму, який не можна було б промоделювати машиною Тюрінга. Тому
на практиці тезу приймають як означення: **алгоритм — це те, що може виконати машина Тюрінга**. Звідси й
висновок для програміста: усі сучасні мови програмування однаково «потужні» за тим, що можна обчислити, і
відрізняються лише зручністю й швидкодією.

## Базові поняття теорії алгоритмів

**Алфавіт** — скінченна непорожня множина символів. **Слово** — скінченна послідовність символів алфавіту;
кількість символів — **довжина** слова; **порожнє слово** $\lambda$ має довжину 0. Будь-які дані можна закодувати
словом: число — рядком цифр, таблицю — рядком із роздільниками, програму — її текстом.

**Вхідні дані й результат.** Алгоритм перетворює вхідне слово на вихідне. Множину вхідних даних, для яких
алгоритм зупиняється й дає результат, називають **областю застосовності** алгоритму.

**Обчислювана функція** — функція, для якої існує алгоритм, що за будь-яким аргументом з області визначення
обчислює її значення. Функція може бути **частковою** — не визначеною для деяких аргументів; тоді алгоритм на цих
аргументах працює нескінченно.

**Розв'язна проблема** (алгоритмічно розв'язна) — масова задача з відповіддю «так» або «ні», для якої існує
алгоритм, що для кожного випадку дає правильну відповідь. Наприклад, «чи є число $n$ простим» — розв'язна
проблема: досить перевірити дільники до $\sqrt{n}$.

**Алгоритмічно нерозв'язні проблеми** існують. Найвідоміша — **проблема зупинки**: не існує алгоритму, який за
текстом будь-якої програми й її вхідними даними визначав би, чи зупиниться програма. Ідея доведення (Тюрінг,
1936): якби такий «аналізатор» існував, з нього можна було б побудувати програму, яка зупиняється тоді й лише
тоді, коли аналізатор каже, що вона не зупиниться, — і прийти до суперечності. Практичний наслідок: жоден
компілятор чи антивірус не може бездоганно передбачити поведінку довільної програми.

**Складність алгоритму.** Для розв'язних задач важливо, **скільки** ресурсів потрібно: часу (кількості кроків) і
пам'яті, залежно від розміру вхідних даних. Алгоритм, який теоретично розв'язує задачу, але працює мільярди років,
практично непридатний. Оцінкам складності присвячено лекцію 13.

## Підсумки

- Слово «алгоритм» походить від імені аль-Хорезмі; алгоритм Евкліда відомий понад два тисячоліття.
- Алгоритм — скінченний набір точних інструкцій для виконавця, що розв'язує клас задач за скінченну кількість
  кроків.
- Основні властивості: дискретність, визначеність, зрозумілість, результативність, масовість; окремо —
  коректність.
- Точне означення алгоритму потрібне, щоб доводити нерозв'язність задач (десята проблема Гільберта, проблема
  розв'язності, проблема зупинки).
- Три підходи до уточнення: рекурсивні функції, абстрактні машини (Тюрінг, Пост), нормальні алгоритми Маркова;
  усі вони рівносильні.
- Теза Черча–Тюрінга: усе, що обчислюється інтуїтивним алгоритмом, обчислюється машиною Тюрінга.
