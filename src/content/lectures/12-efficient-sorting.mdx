Прості методи з лекції 11 виконують порядку $n^2$ операцій: для мільйона елементів — сотні мільярдів порівнянь.
Ефективні методи обходяться порядку $n \log n$ операцій — для того самого мільйона це близько двадцяти мільйонів,
тобто в десятки тисяч разів менше. У цій лекції розберемо сортування Шелла, злиттям, швидке й пірамідальне, а
також сортування підрахунком, яке взагалі не порівнює елементи.

Для трасувань, як і раніше, використовуємо один масив:

$$
a = [5, 2, 7, 1, 9, 3, 8, 4].
$$

## Сортування Шелла

**Ідея.** Сортування вставками повільне, бо елемент рухається до свого місця лише на одну позицію за раз. Дональд
Шелл (1959) запропонував спершу впорядкувати елементи, що стоять на великій відстані $h$ один від одного, а потім
зменшувати відстань. Масив, у якому впорядковані всі підпослідовності з кроком $h$, називають
**$h$-відсортованим**. Останній прохід — звичайні вставки з кроком 1, але на майже впорядкованому масиві вони
працюють швидко.

**Послідовність кроків.** Шелл брав $h = n/2, n/4, \dots, 1$. Кращі результати дає послідовність Кнута
$1, 4, 13, 40, 121, \dots$ ($h_{k+1} = 3h_k + 1$), яку перебирають у зворотному порядку.

### Трасування

Ефект найкраще видно на масиві в зворотному порядку $[8, 7, 6, 5, 4, 3, 2, 1]$ з кроками 4, 2, 1:

| Крок $h$ | Масив після проходу | Переміщень |
| --- | --- | --- |
| 4 | [4, 3, 2, 1, 8, 7, 6, 5] | 4 |
| 2 | [2, 1, 4, 3, 6, 5, 8, 7] | 4 |
| 1 | [1, 2, 3, 4, 5, 6, 7, 8] | 4 |

Разом 12 переміщень, тоді як звичайні вставки на цьому масиві виконують 28. На випадковому масиві з 10 000
чисел різниця ще разючіша: близько 154 тисяч переміщень у Шелла проти понад 25 мільйонів у вставок.

### Реалізація

```cpp
void shellSort(vector<int>& a) {
    int n = a.size();
    for (int h = n / 2; h > 0; h /= 2) {
        for (int i = h; i < n; i++) {          // вставки з кроком h
            int key = a[i];
            int j = i;
            while (j >= h && a[j - h] > key) {
                a[j] = a[j - h];
                j -= h;
            }
            a[j] = key;
        }
    }
}
```

**Аналіз.** Точна трудомісткість залежить від послідовності кроків і досі до кінця не досліджена. Для кроків
Шелла найгірший випадок — $O(n^2)$, для послідовності Кнута — $O(n^{3/2})$. На практиці метод швидкий для
масивів до кількох десятків тисяч елементів. Сортує на місці, **нестійкий**.

## Сортування злиттям

**Ідея — «розділяй і володарюй»** (див. рекурсію в лекції 2):

1. Розділити масив навпіл.
2. Рекурсивно відсортувати кожну половину.
3. **Злити** дві відсортовані половини в одну відсортовану послідовність.

Масив з одного елемента вже відсортований — це базовий випадок рекурсії.

**Злиття** двох відсортованих масивів виконується за один прохід: порівнюємо перші ще не взяті елементи обох
масивів і менший переносимо в результат. Коли один масив вичерпано, дописуємо залишок іншого. Для частин
довжиною $p$ і $q$ це не більше $p + q - 1$ порівнянь.

### Трасування

Дерево рекурсії для нашого масиву (стрілкою показано результат злиття):

```text
[5, 2, 7, 1, 9, 3, 8, 4]                    → [1, 2, 3, 4, 5, 7, 8, 9]
├── [5, 2, 7, 1]                            → [1, 2, 5, 7]
│   ├── [5, 2]                              → [2, 5]
│   └── [7, 1]                              → [1, 7]
└── [9, 3, 8, 4]                            → [3, 4, 8, 9]
    ├── [9, 3]                              → [3, 9]
    └── [8, 4]                              → [4, 8]
```

Останнє злиття $[1, 2, 5, 7]$ і $[3, 4, 8, 9]$ крок за кроком:

| Порівняння | Узято | Результат |
| --- | --- | --- |
| 1 і 3 | 1 | [1] |
| 2 і 3 | 2 | [1, 2] |
| 5 і 3 | 3 | [1, 2, 3] |
| 5 і 4 | 4 | [1, 2, 3, 4] |
| 5 і 8 | 5 | [1, 2, 3, 4, 5] |
| 7 і 8 | 7 | [1, 2, 3, 4, 5, 7] |
| ліва частина вичерпана | 8, 9 | [1, 2, 3, 4, 5, 7, 8, 9] |

### Реалізація

```cpp
void mergeParts(vector<int>& a, int left, int mid, int right, vector<int>& buffer) {
    int i = left, j = mid, k = left;
    while (i < mid && j < right) {
        buffer[k++] = (a[i] <= a[j]) ? a[i++] : a[j++];   // <= зберігає стійкість
    }
    while (i < mid) buffer[k++] = a[i++];
    while (j < right) buffer[k++] = a[j++];
    for (int t = left; t < right; t++) a[t] = buffer[t];
}

void mergeSort(vector<int>& a, int left, int right, vector<int>& buffer) {
    if (right - left <= 1) return;                        // базовий випадок
    int mid = left + (right - left) / 2;
    mergeSort(a, left, mid, buffer);
    mergeSort(a, mid, right, buffer);
    mergeParts(a, left, mid, right, buffer);
}

void mergeSort(vector<int>& a) {
    vector<int> buffer(a.size());
    mergeSort(a, 0, a.size(), buffer);
}
```

**Аналіз.** Глибина рекурсії — $\log_2 n$ рівнів, і на кожному рівні зливається загалом $n$ елементів. Отже,
трудомісткість $\Theta(n \log n)$ **у будь-якому випадку** — і для відсортованого, і для «найгіршого» масиву.
Недолік — додатковий буфер розміром $n$ (пам'ять $O(n)$). Метод **стійкий** (завдяки `<=` під час злиття) і добре
підходить для сортування даних, що не вміщуються в пам'ять, та зв'язних списків.

## Швидке сортування

**Ідея** (Ч. Хоар, 1960):

1. Вибрати **опорний елемент** (pivot).
2. **Розбити** масив: ліворуч — елементи, менші за опорний, праворуч — не менші; опорний — між ними, на своєму
   остаточному місці.
3. Рекурсивно відсортувати ліву й праву частини.

На відміну від злиття, вся робота виконується **до** рекурсивних викликів — під час розбиття, а «зливати» потім
нічого не треба.

### Розбиття Ломуто

Беремо опорним останній елемент. Індекс $i$ вказує на місце для наступного «малого» елемента. Проходимо
масив індексом $j$: якщо $a_j$ менший за опорний, міняємо $a_i$ і $a_j$ та збільшуємо $i$. Наприкінці ставимо
опорний на позицію $i$.

### Трасування

| Відрізок | Опорний | Після розбиття (весь масив) | Позиція опорного |
| --- | --- | --- | --- |
| [5, 2, 7, 1, 9, 3, 8, 4] | 4 | [2, 1, 3, **4**, 9, 7, 8, 5] | 3 |
| [2, 1, 3] | 3 | [2, 1, **3**, 4, 9, 7, 8, 5] | 2 |
| [2, 1] | 1 | [**1**, 2, 3, 4, 9, 7, 8, 5] | 0 |
| [9, 7, 8, 5] | 5 | [1, 2, 3, 4, **5**, 7, 8, 9] | 4 |
| [7, 8, 9] | 9 | [1, 2, 3, 4, 5, 7, 8, **9**] | 7 |
| [7, 8] | 8 | [1, 2, 3, 4, 5, 7, **8**, 9] | 6 |

Після першого ж розбиття 4 стоїть на своєму місці, а зліва від неї — лише менші елементи.

### Реалізація

```cpp
int partition(vector<int>& a, int low, int high) {
    int pivot = a[high];
    int i = low;
    for (int j = low; j < high; j++) {
        if (a[j] < pivot) {
            swap(a[i], a[j]);
            i++;
        }
    }
    swap(a[i], a[high]);          // опорний на остаточне місце
    return i;
}

void quickSort(vector<int>& a, int low, int high) {
    if (low >= high) return;
    int p = partition(a, low, high);
    quickSort(a, low, p - 1);
    quickSort(a, p + 1, high);
}
```

Виклик для всього масиву: `quickSort(a, 0, a.size() - 1)`.

### Аналіз

- **Середній випадок** — $O(n \log n)$: якщо опорний ділить масив приблизно навпіл, рівнів рекурсії близько
  $\log_2 n$. На практиці швидке сортування зазвичай найшвидше серед порівняльних методів — звідси й назва.
- **Найгірший випадок** — $O(n^2)$: якщо опорний щоразу найменший або найбільший, одна частина порожня, і рівнів
  рекурсії $n$. З опорним «останній елемент» так стається на **вже відсортованому** масиві — дуже поширений на
  практиці випадок!
- **Як уникнути:** брати **випадковий** опорний елемент або **медіану трьох** (першого, середнього й останнього).
- Сортує на місці (пам'ять лише на стек рекурсії, у середньому $O(\log n)$), **нестійкий**.

## Пірамідальне сортування

**Двійкова купа (піраміда)** — масив, у якому для кожного $i$ елемент $a_i$ не менший за своїх «нащадків»
$a_{2i+1}$ і $a_{2i+2}$ (якщо вони існують). Масив уявляють як двійкове дерево: корінь $a_0$ — найбільший
елемент.

**Ідея** (Дж. Вільямс, 1964):

1. **Побудувати купу** з масиву: «просіювати» вниз вузли від $n/2 - 1$ до 0. Просіювання міняє вузол із більшим
   нащадком, доки властивість купи не відновиться.
2. **Вибирати максимум:** міняти корінь $a_0$ з останнім елементом купи, зменшувати купу на 1 й просіювати новий
   корінь. Максимуми по черзі стають у кінець масиву.

### Трасування

Побудова купи:

| Просіювання вузла | Масив |
| --- | --- |
| 3 | [5, 2, 7, **4**, 9, 3, 8, **1**] |
| 2 | [5, 2, **8**, 4, 9, 3, **7**, 1] |
| 1 | [5, **9**, 8, 4, **2**, 3, 7, 1] |
| 0 | [**9**, **5**, 8, 4, 2, 3, 7, 1] |

Отримана купа як дерево:

```text
          9
        /   \
       5     8
      / \   / \
     4   2 3   7
    /
   1
```

Вибір максимумів (після вертикальної риски — уже відсортований хвіст):

| Крок | Масив |
| --- | --- |
| 1 | [8, 5, 7, 4, 2, 3, 1 \| 9] |
| 2 | [7, 5, 3, 4, 2, 1 \| 8, 9] |
| 3 | [5, 4, 3, 1, 2 \| 7, 8, 9] |
| 4 | [4, 2, 3, 1 \| 5, 7, 8, 9] |
| 5 | [3, 2, 1 \| 4, 5, 7, 8, 9] |
| 6 | [2, 1 \| 3, 4, 5, 7, 8, 9] |
| 7 | [1 \| 2, 3, 4, 5, 7, 8, 9] |

### Реалізація

```cpp
void siftDown(vector<int>& a, int i, int size) {
    while (true) {
        int largest = i;
        int left = 2 * i + 1, right = 2 * i + 2;
        if (left < size && a[left] > a[largest]) largest = left;
        if (right < size && a[right] > a[largest]) largest = right;
        if (largest == i) return;
        swap(a[i], a[largest]);
        i = largest;
    }
}

void heapSort(vector<int>& a) {
    int n = a.size();
    for (int i = n / 2 - 1; i >= 0; i--) siftDown(a, i, n);   // побудова купи
    for (int end = n - 1; end > 0; end--) {
        swap(a[0], a[end]);                                      // максимум у кінець
        siftDown(a, 0, end);
    }
}
```

**Аналіз.** Просіювання проходить не більше висоти дерева — $\log_2 n$ рівнів. Побудова купи займає $O(n)$,
вибір максимумів — $O(n \log n)$. Отже, $O(n \log n)$ **навіть у найгіршому випадку** і без додаткового масиву.
Метод **нестійкий**. На практиці трохи повільніший за швидке сортування через «стрибки» пам'яттю, але його гарантії
цінні: саме його стандартна бібліотека C++ підключає, коли швидке сортування «загрузає».

## Сортування підрахунком

Усі методи вище **порівнюють** елементи. Якщо ж ключі — цілі числа з невеликого діапазону $[0, k]$, їх можна
відсортувати без жодного порівняння:

1. Порахувати, скільки разів трапляється кожне значення.
2. Вивести кожне значення стільки разів, скільки воно трапилося.

Для масиву $[3, 1, 4, 1, 5, 2, 3, 0]$ і $k = 5$ лічильники дорівнюють $[1, 2, 1, 2, 1, 1]$ (одна нуль, дві одиниці,
…), а результат — $[0, 1, 1, 2, 3, 3, 4, 5]$.

```cpp
void countingSort(vector<int>& a, int k) {       // усі елементи в межах 0..k
    vector<int> count(k + 1, 0);
    for (int x : a) count[x]++;
    int pos = 0;
    for (int value = 0; value <= k; value++) {
        while (count[value]-- > 0) a[pos++] = value;
    }
}
```

**Аналіз:** $O(n + k)$ часу й $O(k)$ пам'яті. Для оцінок студентів, віку, байтів ($k = 255$) це найшвидший метод.
Для довільних чисел (великий $k$) не підходить. Стійку версію, придатну для сортування записів, будують через
префіксні суми лічильників — на ній ґрунтується порозрядне сортування (radix sort).

## Порівняння методів

| Метод | Найкращий | Середній | Найгірший | Пам'ять | Стійкий |
| --- | --- | --- | --- | --- | --- |
| вставками | $O(n)$ | $O(n^2)$ | $O(n^2)$ | $O(1)$ | так |
| Шелла (кроки Кнута) | $O(n \log n)$ | залежить від кроків | $O(n^{3/2})$ | $O(1)$ | ні |
| злиттям | $O(n \log n)$ | $O(n \log n)$ | $O(n \log n)$ | $O(n)$ | так |
| швидке | $O(n \log n)$ | $O(n \log n)$ | $O(n^2)$ | $O(\log n)$ | ні |
| пірамідальне | $O(n \log n)$ | $O(n \log n)$ | $O(n \log n)$ | $O(1)$ | ні |
| підрахунком | $O(n + k)$ | $O(n + k)$ | $O(n + k)$ | $O(k)$ | так* |

\* у версії з префіксними сумами.

Що використовують на практиці? `std::sort` у C++ — **інтроспективне сортування** (introsort): швидке сортування,
яке переходить на пірамідальне, якщо рекурсія стає задовгою, а малі частини досортовує вставками. `std::stable_sort`
— варіант злиття. Сортування в Python і Java для об'єктів — Timsort, гібрид злиття й вставок. Отже, всі методи цієї й
попередньої лекції «працюють» у сучасних бібліотеках разом (лекція 14).

## Підсумки

- Ефективні методи сортування мають трудомісткість $O(n \log n)$ замість $O(n^2)$.
- Шелл упорядковує елементи на великих відстанях, а потім зменшує крок; сортує на місці, нестійкий.
- Злиття — «розділяй і володарюй»: $\Theta(n \log n)$ завжди, стійке, але потребує $O(n)$ додаткової пам'яті.
- Швидке сортування розбиває масив відносно опорного; у середньому найшвидше, але з поганим опорним деградує до
  $O(n^2)$ — рятують випадковий опорний або медіана трьох.
- Пірамідальне сортування використовує двійкову купу: $O(n \log n)$ у найгіршому випадку без додаткової пам'яті.
- Сортування підрахунком не порівнює елементи й працює за $O(n + k)$ для цілих з малого діапазону.
