Алгоритм спочатку придумують, а вже потім записують мовою програмування. Між цими етапами його потрібно
зафіксувати так, щоб ідею зрозумів інший розробник, викладач або ви самі через місяць. Для цього існує кілька
способів представлення алгоритмів: словесний, псевдокод, структурограми, схеми (блок-схеми) і, зрештою, сама
програма. У цій лекції розглянемо псевдокод і структурограми, а графічним схемам за стандартами ЄСПД присвячена
наступна лекція.

## Навіщо записувати алгоритм до програми

Записати алгоритм до програми означає розділити дві різні роботи: **що** робити і **як** це висловити конкретною
мовою. Запис алгоритму:

- допомагає продумати розв'язок до того, як відволікатися на синтаксис C++;
- дає змогу обговорити й перевірити ідею з іншими людьми, які можуть не знати вашої мови програмування;
- є частиною документації: з нього видно, чому програма влаштована саме так;
- спрощує налагодження: помилку в логіці легше помітити в короткому записі, ніж у сотнях рядків коду.

Від будь-якого способу представлення очікують **однозначності** (кожен крок зрозумілий однаково),
**наочності** (структуру видно з першого погляду), **компактності** та зручності перевірки.

## Словесний спосіб

Найпростіший спосіб — пронумеровані кроки природною мовою. Так записують, наприклад, алгоритм Евкліда для
найбільшого спільного дільника (НСД):

1. Ввести натуральні числа $a$ і $b$.
2. Якщо $b = 0$, перейти до кроку 5.
3. Обчислити $r$ — остачу від ділення $a$ на $b$.
4. Покласти $a = b$, $b = r$ і повернутися до кроку 2.
5. Вивести $a$ — це і є НСД.

Коли кроки містять формули, спосіб називають **формульно-словесним**.

**Переваги:** зрозумілий будь-кому, не потребує спеціальних знань. **Недоліки:** природна мова багатозначна
(«повторювати, доки…» — перевіряти умову до чи після дії?), опис швидко розростається, а переходи «перейти до
кроку 2» роблять структуру заплутаною — це прямий аналог оператора `goto`.

## Псевдокод

**Псевдокод** — напівформальна мова запису алгоритмів: ключові слова структурного програмування («якщо»,
«поки», «для») поєднуються зі звичайними математичними виразами й природною мовою. Він не має єдиного стандарту
й не компілюється — це мова для людей. Головна вимога — послідовність: однакові конструкції записують однаково.

### Домовленості нашого курсу

| Конструкція | Псевдокод | C++ |
| --- | --- | --- |
| присвоювання | `x ← вираз` | `x = вираз;` |
| введення, виведення | `ввести x`, `вивести x` | `cin >> x;`, `cout << x;` |
| розгалуження | `якщо умова то … інакше … кінець якщо` | `if (умова) … else …` |
| вибір | `вибір x: випадок 1: … інакше: … кінець вибору` | `switch (x) …` |
| цикл з передумовою | `поки умова виконувати … кінець поки` | `while (умова) …` |
| цикл з післяумовою | `повторювати … поки умова` | `do … while (умова);` |
| цикл з параметром | `для i від 1 до n виконувати … кінець для` | `for (int i = 1; i <= n; i++) …` |
| підпрограма | `функція Ім'я(параметри) … повернути значення` | функція C++ |

Кілька правил оформлення:

- **Відступи показують вкладеність.** Усе, що всередині циклу чи гілки, пишуть з відступом.
- **Одна дія — один рядок.** Складну дію краще розбити або винести в окрему підпрограму.
- **Змістовні імена.** `сума`, `максимум`, `кількістьВідмінників` читаються краще за `s`, `m`, `k`.
- **Без деталей мови.** Типи даних, крапки з комою, дужки й підключення бібліотек у псевдокоді не потрібні.
- Знак `←` читають як «присвоїти»: запис `a ← a + 1` означає «збільшити $a$ на 1», а не рівняння.

### Приклад 1. Найбільше з трьох чисел

```text
ввести a, b, c
max ← a
якщо b > max то
    max ← b
кінець якщо
якщо c > max то
    max ← c
кінець якщо
вивести max
```

Зверніть увагу на прийом: замість перебору всіх шести варіантів упорядкування ми зберігаємо «поточного
кандидата» й по черзі порівнюємо його з рештою. Цей самий прийом працює для масиву будь-якої довжини.

### Приклад 2. Алгоритм Евкліда

```text
функція НСД(a, b)
    поки b ≠ 0 виконувати
        r ← a mod b
        a ← b
        b ← r
    кінець поки
    повернути a
```

Операція `mod` — остача від ділення (у C++ — оператор `%`). Порівняйте з словесним записом: переходи «перейти до
кроку 2» зникли, їх замінив цикл, і структуру видно одразу.

### Приклад 3. Лінійний пошук

Знайти в масиві $a_0, a_1, \dots, a_{n-1}$ позицію першого елемента, що дорівнює $x$, або повідомити, що такого
елемента немає:

```text
ввести n, масив a, x
позиція ← −1
i ← 0
поки i < n і позиція = −1 виконувати
    якщо a[i] = x то
        позиція ← i
    кінець якщо
    i ← i + 1
кінець поки
якщо позиція = −1 то
    вивести «не знайдено»
інакше
    вивести позиція
кінець якщо
```

Той самий алгоритм мовою C++:

```cpp
#include <iostream>
#include <vector>
using namespace std;

int main() {
    int n, x;
    cin >> n;
    vector<int> a(n);
    for (int i = 0; i < n; i++) cin >> a[i];
    cin >> x;

    int position = -1;
    int i = 0;
    while (i < n && position == -1) {
        if (a[i] == x) position = i;
        i++;
    }

    if (position == -1) cout << "не знайдено\n";
    else cout << position << '\n';
}
```

Переклад із псевдокоду вийшов майже механічним: кожна конструкція псевдокоду має пряму відповідність у C++.
Саме це робить псевдокод зручним проміжним етапом.

## Покрокова деталізація

Складну задачу не записують одразу в деталях. Спочатку складають «план верхнього рівня», а потім уточнюють
кожен його пункт — це **покрокова деталізація** (проєктування згори донизу). Наприклад, задача «обробити оцінки
групи»:

```text
ввести оцінки групи
обчислити середній бал
знайти кількість студентів із середнім балом не нижче 4.5
вивести результати
```

На наступному кроці кожен рядок розгортають. Рядок «обчислити середній бал» перетворюється на

```text
сума ← 0
для i від 1 до n виконувати
    сума ← сума + бал[i]
кінець для
середній ← сума / n
```

Деталізацію продовжують, доки кожен рядок не стане очевидним для перекладу мовою програмування. Пункти верхнього
рівня часто стають окремими функціями програми.

## Структурограми (діаграми Нассі–Шнейдермана)

У 1973 році Айзек Нассі та Бен Шнейдерман запропонували графічний запис алгоритмів, розрахований саме на
структурне програмування. Такі схеми називають **діаграмами Нассі–Шнейдермана**, або **структурограмами**.
У Німеччині їх нормує стандарт DIN 66261.

Головна ідея: алгоритм зображують **одним прямокутником**, який ділять на вкладені прямокутні блоки. Стрілок і
ліній переходів немає зовсім — отже, «стрибнути» в довільне місце неможливо. Будь-яку структурограму можна
побудувати лише з трьох базових структур: слідування, розгалуження й циклу.

![Елементи структурограм: слідування, розгалуження, вибір, цикли з передумовою й післяумовою](/files/lectures/08-pseudocode-structograms/ns-elements.svg)
*Рис. 1. Основні елементи структурограм*

### Елементи

- **Слідування.** Дії записують у прямокутники одна під одною; виконують згори донизу.
- **Розгалуження.** У верхній смузі — умова, розділена двома діагоналями на гілки «так» і «ні». Під нею два
  стовпці з діями для кожної гілки. Якщо в гілці нічого не робити, стовпець лишають порожнім або ставлять
  риску.
- **Вибір.** Узагальнення розгалуження на кілька варіантів значення (як `switch` у C++): кожному варіанту —
  свій стовпець.
- **Цикл з передумовою.** Умову записують у верхню смугу, тіло циклу — у прямокутник, зсунутий праворуч.
  Ліва смуга, що охоплює тіло, наочно показує межі циклу. Цикл з параметром («для i від 1 до n») зображують
  так само.
- **Цикл з післяумовою.** Тіло вгорі, умова в нижній смузі: тіло виконається принаймні один раз.

### Правила побудови

1. Структурограму читають згори донизу; кожен блок має один вхід (зверху) й один вихід (знизу).
2. Будь-який блок можна замінити цілою структурою — так виникає вкладеність.
3. Ширина гілок розгалуження ділить ширину батьківського блоку; глибока вкладеність робить блоки вузькими —
   сигнал, що частину алгоритму варто винести в підпрограму.
4. Текст у блоках — короткий псевдокод: `r ← a mod b`, `вивести max`.

Порівняйте з псевдокодом у прикладі 2: кожен рядок став блоком, а цикл «поки $b \ne 0$» охопив три дії тіла.

### Приклад: максимум у масиві

![Структурограма пошуку максимального елемента масиву](/files/lectures/08-pseudocode-structograms/ns-max.svg)
*Рис. 3. Структурограма пошуку максимального елемента*

Тут розгалуження вкладене в цикл: для кожного $i$ перевіряємо, чи $a_i$ більший за поточний максимум. Гілка «ні»
порожня. Відповідна програма:

```cpp
int max = a[0];
for (int i = 1; i < n; i++) {
    if (a[i] > max) max = a[i];
}
cout << max << '\n';
```

## Порівняння способів

| Спосіб | Переваги | Недоліки | Де доречний |
| --- | --- | --- | --- |
| словесний | зрозумілий без підготовки | багатозначний, громіздкий | інструкції для людей, постановка задачі |
| псевдокод | компактний, близький до програми, легко редагувати | немає єдиного стандарту | проєктування, підручники, співбесіди |
| структурограма | наочна структура, неможливий `goto` | важко малювати й змінювати великі алгоритми | навчання структурному програмуванню |
| схема (блок-схема) | стандартизована (ГОСТ 19.701-90), наочна | громіздка, дозволяє заплутані переходи | документація за стандартами, звіти |
| програма | точна, виконується | залежить від мови, перевантажена деталями | реалізація |

На практиці способи поєднують: ідею формулюють словами, проєктують псевдокодом, для документації малюють схему
чи структурограму, а реалізують мовою програмування.

## Від структурограми до програми

Кожен елемент структурограми відповідає конструкції C++, тому переклад виконують «блок за блоком»:

| Елемент | C++ |
| --- | --- |
| блок дії | оператор або виклик функції |
| розгалуження | `if (умова) … else …` |
| вибір | `switch (вираз) …` |
| цикл з передумовою | `while (умова) …` або `for (…) …` |
| цикл з післяумовою | `do … while (умова);` |

Якщо структурограма побудована правильно, у програмі не буде ні `goto`, ні «хитрих» переходів — лише вкладені
структурні конструкції. Про ці конструкції докладніше поговоримо в лекції 10.

## Підсумки

- Алгоритм записують до програми, щоб відокремити логіку від синтаксису мови й мати документацію.
- Словесний спосіб простий, але багатозначний і схильний до переходів «перейти до кроку…».
- Псевдокод поєднує ключові слова структурного програмування з математичними виразами; важлива послідовність
  домовленостей і відступи.
- Покрокова деталізація: план верхнього рівня уточнюють, доки кожен рядок не стане очевидним.
- Структурограми Нассі–Шнейдермана зображують алгоритм як вкладені прямокутники без стрілок; вони складаються
  зі слідування, розгалуження, вибору й циклів.
- Кожна конструкція псевдокоду й структурограми має пряму відповідність у C++.
