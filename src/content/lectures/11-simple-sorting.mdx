Сортування — одна з найчастіших задач у програмуванні: впорядковують списки студентів, результати пошуку,
записи в базах даних, точки перед обробкою графіки. Відсортовані дані легше шукати, об'єднувати й аналізувати.
У цій лекції розглянемо три прості методи сортування — бульбашкою, вибором і вставками: їхню ідею, трасування,
реалізацію мовою C++ і кількість операцій. У наступній лекції перейдемо до ефективних методів.

## Постановка задачі

Дано масив $a_0, a_1, \dots, a_{n-1}$. Потрібно переставити його елементи так, щоб

$$
a_0 \le a_1 \le \dots \le a_{n-1}.
$$

Це сортування **за неспаданням** (за зростанням, якщо однакових елементів немає). Сортування за незростанням
відрізняється лише знаком порівняння.

На практиці сортують не лише числа, а й записи — наприклад, студентів за середнім балом. Поле, за яким
порівнюють, називають **ключем**.

### Характеристики методів

- **Кількість порівнянь** ключів і **кількість переміщень** (обмінів або зсувів) елементів — основні міри
  трудомісткості.
- **Сортування на місці** — метод не потребує додаткового масиву; додаткова пам'ять $O(1)$.
- **Стійкість** — елементи з однаковими ключами зберігають взаємний порядок. Це важливо, коли дані сортують за
  кількома ознаками: спершу за прізвищем, потім стійко за групою — і в межах групи прізвища лишаться за абеткою.
- **Поведінка на різних даних** — найкращий, середній і найгірший випадки.

Для всіх прикладів цієї лекції візьмемо масив

$$
a = [5, 2, 4, 1, 3].
$$

## Сортування бульбашкою

**Ідея.** Проходимо масив зліва направо й порівнюємо сусідні елементи. Якщо лівий більший за правий — міняємо їх
місцями. За один прохід найбільший елемент «спливає», як бульбашка, у кінець масиву. Наступний прохід можна
закінчити на один елемент раніше.

Якщо за прохід не відбулося жодного обміну, масив уже відсортовано — роботу можна припинити. Для цього
використовують **прапорець** (ознаку обміну).

### Трасування

| Прохід | Порівняння й обміни | Масив після проходу |
| --- | --- | --- |
| 1 | (5, 2) обмін, (5, 4) обмін, (5, 1) обмін, (5, 3) обмін | [2, 4, 1, 3, **5**] |
| 2 | (2, 4) —, (4, 1) обмін, (4, 3) обмін | [2, 1, 3, **4**, **5**] |
| 3 | (2, 1) обмін, (2, 3) — | [1, 2, **3**, **4**, **5**] |
| 4 | (1, 2) — ; обмінів не було — зупинка | [1, 2, 3, 4, 5] |

Жирним позначено елементи, що вже стоять на своїх місцях. Разом: 10 порівнянь і 7 обмінів.

### Реалізація

```cpp
void bubbleSort(vector<int>& a) {
    int n = a.size();
    for (int pass = 0; pass < n - 1; pass++) {
        bool swapped = false;
        for (int j = 0; j < n - 1 - pass; j++) {
            if (a[j] > a[j + 1]) {
                swap(a[j], a[j + 1]);
                swapped = true;
            }
        }
        if (!swapped) break;    // обмінів не було — масив відсортовано
    }
}
```

### Аналіз

- У найгіршому випадку (масив упорядкований у зворотному порядку) виконується $n - 1$ проходів, а порівнянь
  $(n-1) + (n-2) + \dots + 1 = \frac{n(n-1)}{2}$. Стільки ж і обмінів.
- У найкращому випадку (масив уже впорядкований) завдяки прапорцю досить одного проходу: $n - 1$ порівнянь.
- Кількість обмінів дорівнює кількості **інверсій** — пар $i < j$, для яких $a_i > a_j$. У нашому масиві їх 7.
- Метод **стійкий**: рівні сусідні елементи не міняються місцями (умова `>`, а не `>=`).

## Сортування вибором

**Ідея.** Знаходимо найменший елемент масиву й ставимо його на перше місце. Потім серед решти знаходимо
найменший і ставимо на друге місце, і так далі. На кроці $i$ масив поділено на відсортовану частину
$a_0, \dots, a_{i-1}$ і невідсортовану, у якій шукаємо мінімум.

### Трасування

| Крок $i$ | Невідсортована частина | Мінімум | Обмін | Масив після кроку |
| --- | --- | --- | --- | --- |
| 0 | [5, 2, 4, 1, 3] | 1 (індекс 3) | $a_0 \leftrightarrow a_3$ | [**1**, 2, 4, 5, 3] |
| 1 | [2, 4, 5, 3] | 2 (індекс 1) | не потрібен | [**1**, **2**, 4, 5, 3] |
| 2 | [4, 5, 3] | 3 (індекс 4) | $a_2 \leftrightarrow a_4$ | [**1**, **2**, **3**, 5, 4] |
| 3 | [5, 4] | 4 (індекс 4) | $a_3 \leftrightarrow a_4$ | [**1**, **2**, **3**, **4**, **5**] |

Разом: $4 + 3 + 2 + 1 = 10$ порівнянь і 3 обміни.

### Реалізація

```cpp
void selectionSort(vector<int>& a) {
    int n = a.size();
    for (int i = 0; i < n - 1; i++) {
        int minIndex = i;
        for (int j = i + 1; j < n; j++) {
            if (a[j] < a[minIndex]) minIndex = j;
        }
        if (minIndex != i) swap(a[i], a[minIndex]);
    }
}
```

### Аналіз

- Кількість порівнянь **завжди** $\frac{n(n-1)}{2}$ — незалежно від вхідних даних: мінімум доводиться шукати
  повністю навіть у відсортованому масиві.
- Обмінів — не більше $n - 1$. Тому метод вигідний, коли переміщення елемента дороге (великі записи), а порівняння
  дешеве.
- Метод **нестійкий**. Приклад: у масиві $[2_a, 2_b, 1]$ перший крок міняє $2_a$ і $1$, і отримуємо
  $[1, 2_b, 2_a]$ — рівні елементи помінялися місцями.

## Сортування вставками

**Ідея.** Так сортують карти в руці: беремо чергову карту й вставляємо її на потрібне місце серед уже
впорядкованих. На кроці $i$ частина $a_0, \dots, a_{i-1}$ уже впорядкована; елемент $a_i$ запам'ятовуємо, а
більші за нього елементи зсуваємо на одну позицію праворуч, звільняючи місце.

### Трасування

| Крок $i$ | Елемент | Зсуви | Масив після кроку |
| --- | --- | --- | --- |
| 1 | 2 | 5 → | [**2**, **5**, 4, 1, 3] |
| 2 | 4 | 5 → | [**2**, **4**, **5**, 1, 3] |
| 3 | 1 | 5 →, 4 →, 2 → | [**1**, **2**, **4**, **5**, 3] |
| 4 | 3 | 5 →, 4 → | [**1**, **2**, **3**, **4**, **5**] |

Жирним — уже впорядкована частина. Разом 9 порівнянь і 7 зсувів (знову стільки, скільки інверсій).

### Реалізація

```cpp
void insertionSort(vector<int>& a) {
    int n = a.size();
    for (int i = 1; i < n; i++) {
        int key = a[i];
        int j = i - 1;
        while (j >= 0 && a[j] > key) {
            a[j + 1] = a[j];    // зсуваємо більший елемент праворуч
            j--;
        }
        a[j + 1] = key;         // вставляємо на звільнене місце
    }
}
```

Зверніть увагу на порядок умов у циклі `while`: спершу перевіряємо `j >= 0`, і лише потім звертаємося до `a[j]`.
Завдяки скороченому обчисленню `&&` друга умова не перевіряється, коли $j = -1$, і програма не виходить за межі
масиву.

### Аналіз

- Найгірший випадок (зворотний порядок): $\frac{n(n-1)}{2}$ порівнянь і зсувів.
- Найкращий випадок (масив відсортований): $n - 1$ порівнянь, жодного зсуву.
- На «майже відсортованих» масивах метод дуже швидкий: кількість зсувів дорівнює кількості інверсій.
- Метод **стійкий** і працює на місці. Його часто використовують для малих масивів (до кількох десятків
  елементів) і як частину ефективних методів (лекція 12).

## Порівняння методів

| Метод | Порівнянь (найгірше) | Переміщень (найгірше) | Найкращий випадок | Стійкий | Пам'ять |
| --- | --- | --- | --- | --- | --- |
| бульбашкою | $\frac{n(n-1)}{2}$ | $\frac{n(n-1)}{2}$ обмінів | $n - 1$ порівнянь | так | $O(1)$ |
| вибором | $\frac{n(n-1)}{2}$ | $n - 1$ обмінів | $\frac{n(n-1)}{2}$ порівнянь | ні | $O(1)$ |
| вставками | $\frac{n(n-1)}{2}$ | $\frac{n(n-1)}{2}$ зсувів | $n - 1$ порівнянь | так | $O(1)$ |

Усі три методи мають **квадратичну** трудомісткість: зі збільшенням масиву вдесятеро час роботи зростає приблизно
в сто разів. Для $n = 10^3$ це близько $5 \cdot 10^5$ порівнянь — миттєво; для $n = 10^6$ — близько
$5 \cdot 10^{11}$, тобто хвилини чи години. Тому для великих масивів потрібні ефективні методи з лекції 12, а
формальну мову оцінок ($O$-нотацію) розглянемо в лекції 13.

На практиці з трьох простих методів найкорисніше сортування вставками: воно стійке, коротке й швидке на малих та
майже впорядкованих масивах.

## Перевірка програми сортування

Сортування легко реалізувати з помилкою на одиницю. Перевіряйте програму на наборі тестів:

- порожній масив і масив з одного елемента;
- уже відсортований масив і масив у зворотному порядку;
- масив з однаковими елементами й масив із повторами;
- масив із від'ємними числами;
- випадкові масиви, результат яких порівнюють зі стандартним `std::sort`.

```cpp
#include <algorithm>
#include <random>

bool testSort(void (*sortFunction)(vector<int>&)) {
    mt19937 rng(42);
    for (int test = 0; test < 1000; test++) {
        vector<int> a(rng() % 50);
        for (int& x : a) x = int(rng() % 21) - 10;   // числа від −10 до 10
        vector<int> expected = a;
        sort(expected.begin(), expected.end());
        sortFunction(a);
        if (a != expected) return false;
    }
    return true;
}
```

Такий «перевіряльник» за частку секунди проганяє тисячу випадкових масивів і майже напевно знайде помилку, якщо
вона є.

## Підсумки

- Сортування впорядковує елементи за ключем; важливі кількість порівнянь і переміщень, стійкість і потрібна пам'ять.
- Бульбашка міняє місцями сусідні елементи; прапорець дає змогу зупинитися, щойно масив відсортовано.
- Вибір щоразу знаходить мінімум невідсортованої частини; порівнянь завжди $\frac{n(n-1)}{2}$, обмінів — не
  більше $n - 1$; метод нестійкий.
- Вставки вставляють черговий елемент у відсортовану частину; найшвидший із простих методів на майже
  впорядкованих даних.
- Кількість обмінів бульбашки й зсувів вставок дорівнює кількості інверсій.
- Усі три методи квадратичні й придатні лише для невеликих масивів.

## Контрольні запитання

1. Сформулюйте задачу сортування. Що таке ключ сортування?
2. Що означає стійкість сортування? Наведіть приклад, коли вона важлива.
3. Опишіть ідею сортування бульбашкою. Навіщо потрібен прапорець обміну?
4. Скільки порівнянь виконує бульбашка в найкращому й найгіршому випадках?
5. Що таке інверсія? Скільки інверсій у масиві [3, 1, 2]?
6. Опишіть ідею сортування вибором. Чому кількість порівнянь не залежить від даних?
7. Покажіть на прикладі, що сортування вибором нестійке.
8. Опишіть ідею сортування вставками. Чому воно швидке на майже впорядкованих масивах?
9. Чому в циклі сортування вставками умову `j >= 0` перевіряють першою?
10. Протрасуйте три методи на масиві [4, 3, 2, 1].
11. Яка трудомісткість простих методів? Як зміниться час роботи, якщо масив збільшити вдвічі?
12. Як перевірити правильність програми сортування?
