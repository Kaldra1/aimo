# АІМО — сайт курсу «Алгоритми і методи обчислень»

Відкритий довідник і тренажер курсу для студентів спеціальності 123 «Комп'ютерна інженерія»
(3 курс, 5 семестр): лекції, лабораторні роботи, практичні заняття, емулятори алгоритмічних машин
і задачі з автоматичною перевіркою.

Сайт: https://kaldra1.github.io/aimo/

Сайт статичний: без реєстрації, бекенду, cookies, аналітики й сторонніх CDN. Оцінки, реєстрація
та здача робіт лишаються в Moodle.

## Запуск на своєму комп'ютері

1. Встановіть [Node.js](https://nodejs.org/) версії 22.12 або новішої (рекомендовано 24 LTS).
2. У папці проєкту виконайте:

   ```bash
   npm install
   npm run dev
   ```

3. Відкрийте http://localhost:4321/aimo/ — сторінки оновлюються одразу після збереження файлів.

У режимі `npm run dev` чернетки (`draft: true`) видно повністю з позначкою «Чернетка». На
опублікованому сайті вони показуються як «Скоро».

| Команда           | Що робить                                                          |
| ----------------- | ------------------------------------------------------------------ |
| `npm run dev`     | локальний сайт для роботи з матеріалами                            |
| `npm test`        | тести (зокрема перевірка всіх лекцій і занять)                     |
| `npm run build`   | перевірка типів і збирання сайту в папку `dist/`                   |
| `npm run preview` | перегляд зібраного сайту так, як його побачать студенти            |
| `npm run lint`    | перевірка коду ESLint                                              |
| `npm run format`  | автоформатування коду Prettier (контент у `src/content/` не чіпає) |

## Як додати або змінити лекцію

Лекції лежать у `src/content/lectures/`, один файл — одна лекція. Щоб додати нову:

1. Скопіюйте файл `_template.mdx` (файли, що починаються з `_`, на сайт не потрапляють).
2. Назвіть копію латиницею за зразком `21-latin-name.mdx`. З назви утвориться адреса сторінки:
   `/lectures/21-latin-name/`. Лише малі латинські літери, цифри й дефіси.
3. Заповніть поля між рисками `---` (див. таблицю).
4. Нижче другої риски напишіть текст лекції.
5. Коли лекція готова, поставте `draft: false`.

| Поле      | Обов'язкове | Значення                                                                                   |
| --------- | ----------- | ------------------------------------------------------------------------------------------ |
| `number`  | так         | номер лекції; визначає порядок і кнопки «Попередня / Наступна»                             |
| `title`   | так         | назва лекції                                                                               |
| `module`  | так         | номер змістового модуля з `src/data/course.yaml`                                           |
| `topic`   | так         | номер теми з `src/data/course.yaml`                                                        |
| `slides`  | ні          | шлях до PDF слайдів (див. нижче)                                                           |
| `related` | ні          | пов'язані сторінки: `labs/1`, `practicals/2`, `lectures/03-post-machine`, `emulators/post` |
| `draft`   | ні          | `true` — чернетка («Скоро» на сайті), `false` — опубліковано                               |

Приклад:

```mdx
---
number: 3
title: 'Машина Поста'
module: 1
topic: 2
slides: '/files/slides/lecture-03.pdf'
related: ['labs/1', 'emulators/post']
draft: false
---

Машина Поста — абстрактна обчислювальна машина...

## Будова машини

Стрічка складається з комірок...
```

### Як писати текст

- Заголовки розділів — `## Назва`, підрозділів — `### Назва`. З заголовків `##` сайт будує зміст
  сторінки.
- Формули (KaTeX): у рядку `$a^2 + b^2 = c^2$`, окремим блоком — між рядками `$$`.
- Код: блок між рядками ` ```cpp ` і ` ``` `.
- Посилання на інші сторінки сайту пишіть від кореня: `[ЛР1](/labs/1/)`. Префікс `/aimo`
  сайт додасть сам.
- Картинки покладіть у `public/files/` і вставляйте так: `![Схема](/files/scheme.png)`.

**Увага: фігурні дужки й знак `<` у файлах `.mdx`.** MDX сприймає `{…}` у звичайному тексті як
код: наприклад, «{1, 2, 3}» на сторінці перетвориться на «3». Знак `<` перед літерою MDX вважає
початком компонента. Пишіть такі фрагменти у формулах (`$\{1, 2, 3\}$`, `$a < b$`) чи в коді
(`` `a<b` ``) або екрануйте: `\{`, `\}` і `&lt;`. Якщо таких символів у тексті багато, назвіть файл
`.md` замість `.mdx`: тоді їх можна писати як є.

## Як додати лабораторну роботу або практичне заняття

Заняття лежать у `src/content/sessions/`:

1. Скопіюйте `_template-lab.mdx` (лабораторна) або `_template-practical.mdx` (практичне).
2. Назвіть копію `lab-05.mdx` або `practical-05.mdx`. Адреса сторінки утворюється з номера:
   `/labs/5/`, `/practicals/5/`.
3. Заповніть поля й текст під стандартними заголовками. Шаблон уже містить розділи в правильному
   порядку: Мета, Обладнання, Основні теоретичні положення, Хід роботи, Варіанти, Зміст звіту (для
   лабораторних), Контрольні запитання, Домашнє завдання (для практичних). Тема роботи — це поле
   `title`.

| Поле       | Обов'язкове | Значення                                                        |
| ---------- | ----------- | --------------------------------------------------------------- |
| `kind`     | так         | `"lab"` — лабораторна, `"practical"` — практичне                |
| `number`   | так         | номер роботи                                                    |
| `title`    | так         | тема роботи                                                     |
| `hours`    | так         | кількість годин                                                 |
| `topic`    | так         | номер теми з `src/data/course.yaml`                             |
| `emulator` | ні          | кнопка «Відкрити емулятор»: `"post"`, `"turing"` або `"markov"` |
| `draft`    | ні          | `true` — чернетка, `false` — опубліковано                       |

## Модулі й теми курсу

Назви курсу, змістових модулів і тем задані у файлі `src/data/course.yaml`. Номери тем наскрізні:
саме на них посилаються поля `topic` у лекціях і заняттях.

## Слайди лекцій (PDF)

1. Покладіть PDF у папку `public/files/slides/`, наприклад `public/files/slides/lecture-03.pdf`.
2. У лекції вкажіть `slides: "/files/slides/lecture-03.pdf"` — шлях без `public` і без `/aimo`.
3. На сторінці лекції з'явиться кнопка «Слайди (PDF)», у списку лекцій — посилання.

Якщо файлу немає, збирання зупиниться з поясненням. Можна також дати повну адресу, наприклад
`slides: "https://example.com/lecture-03.pdf"`.

## Як працює публікація

Кожне надсилання змін (push) у гілку `main` запускає GitHub Actions
(`.github/workflows/deploy.yml`):

1. встановлення залежностей, тести (`npm test`) і збирання (`npm run build`);
2. якщо все пройшло, сайт оновлюється на https://kaldra1.github.io/aimo/ за хвилину-дві.

Якщо тести або збирання впали, сайт лишається попереднім, а на вкладці **Actions** на GitHub
з'являється червоний хрестик із текстом помилки (наприклад, «Лекція «21-x»: теми 7 немає в
course.yaml»). Окремий крок перевіряє стиль коду, але публікацію не блокує.

Одноразове налаштування репозиторію: **Settings → Pages → Build and deployment → Source: GitHub
Actions**.

## Структура репозиторію

```
src/
  content/
    lectures/      лекції (.mdx) і шаблон _template.mdx
    sessions/      лабораторні й практичні (.mdx) і шаблони
    pages/         тексти окремих сторінок (about.md — «Про курс»)
  data/course.yaml назва курсу, модулі й теми
  pages/           сторінки сайту (маршрути)
  components/      компоненти інтерфейсу
  layouts/         загальний макет сторінки
  lib/             логіка: структура курсу, посилання, Markdown-плагіни
  styles/          дизайн-токени й стилі
public/files/      PDF слайдів та інші файли
tests/             перевірка контенту й контрасту кольорів
```
