Лекція 1 · Означення01

Що таке алгоритм

Алгоритм — це скінченна система однозначних правил, яка за скінченне число кроків перетворює вхідні дані на результат.

У математиці

Спосіб обчислити функцію

У програмуванні

Логічна послідовність операцій над даними

У житті

Інструкція, яку можна виконати не думаючи

Слово походить від імені перського математика аль-Хорезмі (бл. 780–850). Його трактат про індійський рахунок у латинському перекладі починався словами Dixit Algorizmi — «Сказав аль-Хорезмі». Звідси ж і назва його другої книги «аль-джабр» → алгебра.

Лекція 2 · Постановка02

Дві версії того самого пошуку

Завершиться завжди
for (int i = 0; i < grid.size(); ++i)
    if (!grid.isOccupied(i))
        return i;
return -1;   // чесно: вільних немає

Кількість кроків обмежена наперед розміром сітки. Гірший випадок відомий до запуску.

Як пощастить
int i = 0;
while (grid.isOccupied(i))
    ++i;
return i;

Кількість кроків залежить від даних. Верхньої межі немає.

Уся сьогоднішня лекція — про цю різницю. Математики формалізували її ще у 1930-х, за десять років до появи першого комп'ютера. Ліва колонка — це примітивно-рекурсивні функції. Права — частково-рекурсивні.
Лекція 2 · Базові функції03

Уявіть Blueprint, у якому лише три ноди

Питання: що з цього взагалі можна зібрати?

Нода «нуль»

O(x) = 0

Вихід завжди 0, вхід ігнорується

Нода «+1»

S(x) = x + 1

Додає одиницю до входу

Нода «вибрати вхід»

Iⁿₘ(x₁, …, xₙ) = xₘ

З кількох входів пропускає далі один, вказаний номером

Третя нода виглядає безглуздо — вона нічого не рахує. Але без неї не можна ані переставити аргументи місцями, ані використати один аргумент двічі. У Shader Graph таку ноду теж не помічають, доки не знадобиться розвести проводи.
I³₂(7, 4, 9) = 4 — три входи, беремо другий
Лекція 2 · Оператори04

Оператор 1: суперпозиція

Вихід однієї ноди — на вхід іншої

f(x₁, …, xₘ) = g( f₁(x̄), f₂(x̄), …, fₙ(x̄) )

m-місна функція f отримана суперпозицією з n-місної g та m-місних f₁ … fₙ.

Збираємо константу 3 з двох нод
0 ──► +1 ──► +1 ──► +1 ──► 3

3 = S( S( S( O(x) ) ) )

Так само будується будь-яка константа. Це вже не порожній редактор — з нього щось виходить.

Лекція 2 · Оператори05

Оператор 2: примітивна рекурсія

Стан на кроці y+1 через стан на кроці y

Формальна схема
f(x̄, 0)   = g(x̄)                ← база
f(x̄, y+1) = h(x̄, y, f(x̄, y))    ← крок

(n+1)-місна f будується з n-місної g та (n+2)-місної h. Значення при y+1 читає вже обчислене значення при y.

Позиція об'єкта по кадрах
// pos[0] — стартова позиція
// pos[y+1] будується з pos[y]
for (int y = 0; y < frames; ++y)
    pos[y + 1] = pos[y] + velocity * dt;

Стартове значення — це база. Формула переходу до наступного кадру — це крок. Кількість кадрів відома наперед.

Ключова властивість: y зменшується до нуля гарантовано, бо на кожному кроці зменшується рівно на одиницю. Такий цикл не може зависнути в принципі — і це не побажання, а наслідок самої схеми.
Лекція 2 · Оператори06

Оператор 3: мінімізація

Той самий спавнер із другого слайда

M y ( f(x̄, y) = 0 )

Найменше y, при якому рівність виконується. Перебираємо y = 0, 1, 2, … по порядку.

Сценарій A — вільна клітинка є
y = 0  зайнято ✗
y = 1  зайнято ✗
y = 2  зайнято ✗
y = 3  вільно  ✓
Результат 3 — перебір завершився
Сценарій B — вільних немає
y = 0  зайнято ✗
y = 1  зайнято ✗
y = 2  зайнято ✗
…
Перебір не завершується
Це не помилка реалізації, а властивість самого оператора: якщо розв'язку не існує, функція для цих аргументів не визначена, а програма зависає. Мінімізація дає силу — і одразу забирає гарантію завершення.

ПРФ

Лекція 2 · Чому це працює08

Чому ПРФ завершується завжди

Без доведень — на пальцях

1

Три базові ноди завжди дають результат. O, S, Iⁿₘ — жодна з них нічого не шукає й ні на що не чекає.

2

Провід між нодами нічого не ламає. Якщо всі ноди в схемі дають результат — уся схема теж дає результат.

3

Цикл із лічильником теж нічого не ламає. y зменшується на одиницю щокроку, до нуля дійде обов'язково.

Функція ПРФ збирається зі скінченної кількості таких кроків. Жоден із них не вміє зависати — отже, не вміє й уся конструкція. Кожна ПРФ визначена для будь-яких вхідних даних.
Зворотне невірно. Існують функції, які завершуються завжди, але зібрати їх лише циклами з лічильником неможливо. Про це — на слайді про функцію Аккермана.
Лекція 2 · Приклад 109

Задача: зібрати x + y з трьох нод

Ноди «додати» в нашому редакторі немає

Схема примітивної рекурсії
x + 0     = I¹₁(x) = x     ← база: «вибрати вхід»
x + (y+1) = S(x + y)       ← крок: «+1» від попереднього

Обидва рядки використовують лише дозволені для ПРФ оператори. Отже, x + y — примітивно-рекурсивна.

Те саме мовою C++
int add(int x, int y) {
    if (y == 0) return x;      // база
    return add(x, y - 1) + 1;  // крок
}

Жодного + між змінними — тільки інкремент і рекурсія. Це компілюється й працює.

Розгортка 3 + 2
3+2 → S(3+1) → S(S(3+0)) → S(S(3)) → S(4) → 5
Лекція 2 · Приклад 210

Задача: зібрати x · y

Схема
x · 0     = 0              ← база: нода «нуль»
x · (y+1) = (x · y) + x    ← крок: додавання
База — нуль-функція: g = 0
Крок: h(x, y, f) = f + x
Так само працює будь-який проєкт

Ви не пишете рендер із нуля щоразу — ви користуєтесь тим, що вже написано й перевірено. Тут те саме: функції, для яких рекурсивність доведено, стають цеглинками для наступних.

Порядок побудови
S(x) x + y x · y xʸ x!

Лекція 2 · Приклад 311

Чому здоров'я не буває від'ємним

int applyDamage(int hp, int dmg) {
    return std::max(0, hp - dmg);
}

Ви писали це сто разів. У теорії рекурсивних функцій воно має назву — усічене віднімання, hp ∸ dmg.

Звичайне x − y

На множині N ∪ {0} від'ємних чисел не існує: 3 − 5 не визначене. Це часткова функція.

Усічене x ∸ y

При x < y дає 0: 3 ∸ 5 = 0. Визначене завжди.

Схема побудови
0 ∸ 1     = 0            ← нода «нуль»
(x+1) ∸ 1 = x            ← нода «вибрати вхід»

x ∸ 0     = x
x ∸ (y+1) = (x ∸ y) ∸ 1

Спершу зібрали ∸ 1, потім через нього — ∸ y. Усе на дозволених операторах, отже x ∸ y — ПРФ.

Тому в іграх ніколи не показують «−12 HP». Не тому, що це негарно, а тому, що система здоров'я живе на невід'ємних цілих — і clamp тут не косметика, а спосіб лишитись у межах визначеної функції.

Скільки шкоди потрібно, щоб добити?

Ворог має x HP, ви вже нанесли y. Скільки лишилось? Це справжнє віднімання, не усічене — і зібрати його циклом із лічильником не вийде.

x − y = M z ( y + z = x )

Найменше z, при якому y + z = x. Перебираємо z від нуля.

Ворог мав 5 HP, нанесли 3
z = 0 → 3 + 0 = 3 ≠ 5
z = 1 → 3 + 1 = 4 ≠ 5
z = 2 → 3 + 2 = 5 ✓
Лишилось 2
Ворог мав 3 HP, нанесли 5
z = 0 → 5 ≠ 3
z = 1 → 6 ≠ 3
z = 2 → 7 ≠ 3
…
Перебір не завершується
Другий випадок — рівно та сама ситуація, що й зі спавнером на початку лекції. Розв'язку немає, перебір нескінченний, функція не визначена. x − y — частково-рекурсивна, але не примітивно-рекурсивна.
Лекція 2 · Межа ПРФ / ЗРФ13

Функція Аккермана

Завершується завжди. Дочекатись — не завжди

Означення
A(0, n) = n + 1
A(m, 0) = A(m − 1, 1)
A(m, n) = A(m − 1, A(m, n − 1))

Рекурсія за двома аргументами, причому один виклик стоїть усередині іншого як аргумент. Схема примітивної рекурсії такого не дозволяє — там на кожному кроці зменшується рівно один лічильник.

Зростання
A(1, 1)= 3 A(2, 2)= 7 A(3, 3)= 61 A(4, 2)= 2⁶⁵⁵³⁶ − 3  19 729 цифр A(4, 4)більше за кількість атомів у Всесвіті
Аккерман завершується для будь-яких аргументів — отже, він загальнорекурсивний. Але зібрати його циклами з лічильником неможливо — отже, він не примітивно-рекурсивний. Це і є та функція, що живе між ПРФ і ЗРФ.
Практичний висновок для розробника: «алгоритм гарантовано завершиться» й «алгоритм можна запустити» — різні твердження. Друге сильніше.
Лекція 2 · Практика14

Навіщо це знати на роботі

while в Tick()

На кадр є 16 мілісекунд. Цикл без гарантованої межі всередині ігрового циклу означає не «повільно», а фриз. Тому в коді, що виконується щокадру, або for з межею, або лічильник ітерацій з аварійним виходом.

Стандарти безпечного коду

MISRA C для автомобільної електроніки й DO-178C для авіоніки вимагають, щоб для кожного циклу існувала доказова верхня межа ітерацій. Формально це вимога, щоб код був примітивно-рекурсивним.

Шейдери на GPU

Компілятор розгортає цикли, тому межа має бути відома на етапі компіляції. while зі змінною умовою часто просто не збирається.

Процедурна генерація

«Згенерувати кімнату, що задовольняє умови» через while — це мінімізація в чистому вигляді. Якщо умови суперечливі, генератор зависне. Робоче рішення: обмежити кількість спроб і чесно повернути відмову.

А чи можна написати аналізатор, який для будь-якого коду скаже, зависне він чи ні? Ні, не можна. Це доведено, і називається проблемою зупинки. Дійдемо до неї, коли розберемо машину Тюрінга.
